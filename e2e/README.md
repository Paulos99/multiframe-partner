# Read-only smoke продакшена

Проверяет уже задеплоенный кабинет. Набор ничего не создаёт, не меняет и не удаляет. Перехватчик пропускает `GET`/`HEAD`/`OPTIONS` и `POST /auth/login`. `POST /analytics/events` получает локальный ответ 200 и на сервер не уходит. Любой другой `POST`/`PATCH`/`PUT`/`DELETE` обрывается до сервера, и тест падает. В отчёт попадают метод и путь, без тела и query.

Зависимости живут только в этой папке. `apps/*` не меняется.

Локальный файл `e2e/.env` подхватывается, только если одноимённая переменная ещё пустая. Файл в `.gitignore`. Не коммитьте его.

В GitHub Actions тот же набор запускается вручную: workflow `e2e smoke`, событие `workflow_dispatch`. Секреты называются так же, как переменные выше.

## Запуск

```bash

npx playwright install chromium
npm test
```

Скриншоты появляются в `e2e/artifacts/` (папка не коммитится): `{desktop|mobile}-{role}-home.png`, `-list.png`, `-training.png`, плюс карточка монтажника и два списка для проверки изоляции компаний.

## Что проверяется

Для каждой роли: вход, своя главная, список и раздел «Обучение» (материалы и личная инструкция). У админа главная — обзор сети. У остальных ролей отдельной сводки нет: её убрали, на месте список объектов или заданий и подзаголовок кабинета. У админа списка объектов нет — открывается список партнёров, в нём обе компании. У монтажника проверяется объект «ТЕСТ доступ монтажника»: на экране и в `GET /objects` нет цен и нет сметы, спецификация открывается (`200`), чужая смета по тому же объекту — `404`. Владелец той же компании получает оба файла. Владелец второй компании не видит объекты первой, и наоборот. Блок «Проекты» только открывается, кнопка «Новый проект» не нажимается. Те же сценарии идут на ширине 390px; страница не должна разъезжаться по горизонтали.
