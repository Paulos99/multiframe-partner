Разработка веб-инструмента "MultiFrame Проблемомер"

Ты выступаешь как команда из 4 специалистов одновременно:

1. Product Manager цифровых продуктов
2. UX/UI Lead Designer
3. Frontend Architect
4. Эксперт по веб-сервисам для строительных продуктов

Твоя задача — разработать концепцию и первый прототип веб-инструмента
"MultiFrame Проблемомер" для компании StP.

Перед началом разработки внимательно изучи все приложенные материалы:
- расшифровку разговора с маркетологом;
- письма коммерческого директора;
- концепцию веб-инструмента MultiFrame Проблемомер.

Эти материалы являются главным источником требований.
Не придумывай новую концепцию, а переводи существующую бизнес-логику в цифровой продукт.

==================================================
1. КОНЦЕПЦИЯ ПРОДУКТА
==================================================

Создаваемый инструмент — это не обычный калькулятор материалов.

Главная задача:

Сформировать у пользователя понимание ценности акустического комфорта помещения.

Инструмент должен работать не только для людей, которые уже жалуются:
"Я слышу соседей сверху".

Большая часть потенциальных клиентов не осознаёт необходимость звукоизоляции потолка при выборе натяжного потолка.

Поэтому правильная логика:

Текущий уровень комфорта помещения
↓
Какие типы шума могут присутствовать
↓
Как пользователь воспринимает комфорт
↓
Как изменится помещение после установки StP MultiFrame
↓
Расчёт решения

Главная идея:

Пользователь должен захотеть улучшить помещение,
а не только искать решение уже существующей проблемы.

==================================================
2. ФОКУС ПЕРВОЙ ВЕРСИИ
==================================================

Первая версия инструмента ограничена:

Объект:
- потолок помещения

Источник:
- шум через межэтажное перекрытие

Решение:
- БЕСКАРКАСНАЯ СИСТЕМА ЗВУКОИЗОЛЯЦИИ ПОТОЛКА StP MULTIFRAME

Не включать:
- стены;
- перегородки;
- полы;
- Polyblock;
- каркасные системы;
- другие продукты StP.

==================================================
3. ЦЕЛЕВАЯ АУДИТОРИЯ
==================================================

Основные пользователи:

1. Клиент, выбирающий натяжной потолок.
2. Менеджер по продаже натяжных потолков.
3. Монтажник / партнёр StP.

==================================================
4. ОСНОВНОЙ USER FLOW
==================================================

Экран 1.
Проверка уровня акустического комфорта помещения.

Не спрашивать:
"У вас есть проблема с шумом?"

Использовать:
"Проверьте уровень акустического комфорта вашего помещения".

Экран 2.
Описание помещения:
- тип помещения;
- площадь;
- планируемый потолок.

Экран 3.
Проверка сценариев шума:
- шаги сверху;
- падение предметов;
- мебель;
- разговоры;
- телевизор;
- музыка;
- ремонт.

Экран 4.
Визуализация текущего состояния.

Показать:
- какие звуки могут проникать;
- насколько они заметны;
- почему это происходит.

Экран 5.
Сценарий улучшения.

Сравнение:

До:
обычный потолок

После:
потолок + бескаркасная система StP MultiFrame

Экран 6.
Аудиодемонстрация "Услышать разницу".

Экран 7.
Переход:
- расчёт материалов;
- консультация;
- заявка.

==================================================
5. UX-ПРИНЦИПЫ
==================================================

Интерфейс должен быть:
- понятным;
- визуальным;
- эмоциональным;
- объясняющим.

Не начинать с:
Rw
Lnw
дБ

Сначала:
"Что вы слышите?"
"Какой комфорт хотите получить?"

==================================================
6. ЭКРАН РЕЗУЛЬТАТА
==================================================

Создать экран:

"Акустический профиль помещения"

Структура:

1. Текущее состояние.
2. Источники возможного шума.
3. Почему это происходит.
4. Текущий уровень комфорта.
5. Прогноз после StP MultiFrame.
6. Аудио до/после.
7. Следующий шаг.

==================================================
7. МАТЕМАТИЧЕСКАЯ МОДЕЛЬ
==================================================

Не создавать ложный инженерный расчёт.

Первая версия — экспертная модель оценки.

Вход:
- тип помещения;
- сценарий шума;
- параметры перекрытия (если известны);
- площадь потолка.

Выход:
- текущий уровень комфорта;
- прогнозируемое изменение после StP MultiFrame.

Численные показатели добавлять только после подтверждения техническими данными.

==================================================
8. АУДИОМОДЕЛЬ
==================================================

Создать модуль:

"Услышать разницу"

Сценарии:
- шаги;
- мебель;
- падение предметов;
- телевизор;
- разговоры;
- ремонт.

Важно:
это демонстрация принципа изменения восприятия,
а не точная симуляция конкретной квартиры.
