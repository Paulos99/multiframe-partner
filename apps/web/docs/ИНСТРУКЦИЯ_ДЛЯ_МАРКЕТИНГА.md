# Инструкция для команды интернет-маркетинга — Проблемомер

Документ для людей, которые **ведут трафик, размещают ссылки и смотрят статистику**.  
Код трогать не нужно. Заявки и телефоны из Проблемомера **не собираются**.

---

## 1. Что это за сайт

**Проблемомер** — веб-инструмент диагностики акустического комфорта под MultiFrame (StP).  
Человек отвечает на вопросы о комнате → видит ориентир «сейчас / с MultiFrame» → может:

- открыть **калькулятор** материалов;
- перейти на сайт StP за **консультацией**;
- скачать **PDF** или **поделиться** ссылкой.

Сейчас продукт живёт на GitHub Pages:

**[https://paulos99.github.io/multiframe-problemomer/](https://paulos99.github.io/multiframe-problemomer/)**

Политика (коротко, для баннера cookies):

**[https://paulos99.github.io/multiframe-problemomer/privacy.html](https://paulos99.github.io/multiframe-problemomer/privacy.html)**

## 2. Что уже внедрено по аналитике (с нашей стороны)

В код встроено два слоя. Оба **анонимные** — без имени, телефона, email и без CRM.

### Слой A — Яндекс.Метрика (воронка и кнопки)

После согласия пользователя в баннере cookies подключается счётчик. Считаются события:


| Имя события (цель) | Что означает                             |
| ------------------ | ---------------------------------------- |
| `pm_start`         | Нажали «Начать», пошли в анкету          |
| `pm_room_step`     | Перешли к следующему вопросу             |
| `pm_result_view`   | Дошли до экрана результата               |
| `pm_cta_calc`      | Клик «Рассчитать количество MultiFrame»  |
| `pm_cta_consult`   | Клик «Запросить консультацию или подбор» |
| `pm_share`         | Поделиться                               |
| `pm_pdf`           | Скачать PDF                              |
| `pm_audio_play`    | Включили демо-аудио До/После             |


К событиям цепляется канал (откуда пришли) и параметры сегмента (тип дома, этап объекта, классы комфорта и т.п.) — когда они уже известны.

**Без номера счётчика в секретах Метрика на сайте не появится** (баннер тоже не покажется).

### Слой B — база прохождений (сегменты спроса)

Когда человек **дошёл до результата**, сайт один раз отправляет обезличенный JSON на указанный вами URL:

- откуда пришёл (UTM / партнёр / менеджер);
- ответы анкеты (дом, плита, площадь, этап, задача и т.д.);
- расчётный ориентир до/после MultiFrame.

Это удобно складывать в **Google Таблицу** (инструкция ниже). Оттуда можно строить срезы: «какие дома чаще», «какой канал доводит до результата», «какой класс комфорта преобладает».

**Без URL приёмника** строки в таблицу не пишутся (сайт при этом работает как обычно).

### Чего нет и не будет «из коробки»

- Формы «оставьте телефон» внутри Проблемомера  
- Отправки лидов в Amo / Bitrix / Telegram  
- Личных кабинетов и авторизации

Консультация ведёт на **stp-multiframe.ru** — заявка там, если пользователь сам её оставит.

## 3. Секреты: что завести и куда

Секреты нужны, чтобы при **сборке и выкладке** сайта подставились Метрика и адрес таблицы.  
Хранятся в GitHub репозитория (не в чатах и не в рекламных кабинетах).

Репозиторий: **[https://github.com/Paulos99/multiframe-problemomer](https://github.com/Paulos99/multiframe-problemomer)**

Путь: **Settings → Secrets and variables → Actions → New repository secret**


| Имя секрета (точно так)     | Что положить внутрь                                               | Кто обычно готовит                       |
| --------------------------- | ----------------------------------------------------------------- | ---------------------------------------- |
| `VITE_YM_ID`                | Номер счётчика Яндекс.Метрики (только цифры, например `98765432`) | Маркетинг / аналитик                     |
| `VITE_ANALYTICS_INGEST_URL` | HTTPS-ссылка веб-приложения Google Apps Script (приёмник строк)   | Маркетинг + тот, у кого доступ к таблице |


После сохранения секретов нужно **пересобрать сайт** (см. раздел 4), иначе на уже залитой версии старые настройки.

Локально разработчикам то же самое лежит в файле `.env` по образцу `.env.example` — маркетингу это не обязательно.

## 4. Как «залить сайт на хостинг» (текущая схема)

Сейчас хостинг = **GitHub Pages**. Отдельный FTP/VPS не нужен.

### Автоматически

1. Любой пуш в ветку `main` (или ручной запуск workflow)
2. GitHub Actions собирает сайт **с секретами**
3. Публикует на
  `https://paulos99.github.io/multiframe-problemomer/`

Проверить деплой: в репозитории вкладка **Actions** → workflow **Deploy to GitHub Pages** → зелёная галочка.

### После смены секретов

1. Settings → Secrets → обновили `VITE_YM_ID` и/или `VITE_ANALYTICS_INGEST_URL`
2. Actions → **Deploy to GitHub Pages** → **Run workflow** (ветка `main`)
3. Подождать 1–3 минуты
4. Открыть сайт в режиме инкогнито и проверить (раздел 7)



### Если позже перенесёте на другой хостинг

Нужно, чтобы при сборке фронта в окружение попали те же две переменные (`VITE_YM_ID`, `VITE_ANALYTICS_INGEST_URL`), а на хост уехала папка `dist` после `npm run build`.  
Иначе Метрика и таблица «отвалятся». Это делает тот, кто настраивает новый хостинг; маркетингу достаточно передать ему эти два значения.

## 5. Подключить Яндекс.Метрику (пошагово)

1. Создайте счётчик на [metrika.yandex.ru](https://metrika.yandex.ru/) для адреса сайта Проблемомера.
2. Скопируйте **номер счётчика** → секрет `VITE_YM_ID`.
3. В счётчике создайте цели типа **«JavaScript-событие»** с именами **точно** как в таблице раздела 2 (`pm_start`, `pm_result_view`, `pm_cta_calc` и т.д.).
4. Пересоберите сайт (раздел 4).
5. Откройте сайт → примите cookies → пройдите до результата → в Метрике через несколько минут должны появиться хиты и цели.

Рекомендуемые «главные» цели для отчётов и рекламы:

- `pm_result_view` — дошёл до итога;  
- `pm_cta_calc` / `pm_cta_consult` — клики по продающим кнопкам.

## 6. Подключить таблицу прохождений (Google Sheets)

Готовый скрипт лежит в репозитории: `docs/analytics-ingest.gs`.

1. Создайте Google Таблицу. В первой строке заголовки:
  `timestamp | sessionId | channelLabel | houseType | roomType | area | objectStage | classBefore | classAfter | deltaRw | deltaLnw | json`
2. **Расширения → Apps Script** — вставьте код из `analytics-ingest.gs`, сохраните.
3. **Развернуть → Новое развёртывание → Веб-приложение**:
  - выполнять от имени: **меня**;  
  - доступ: **всем** (иначе сайт с другого домена не сможет писать).
4. Скопируйте URL веб-приложения → секрет `VITE_ANALYTICS_INGEST_URL`.
5. Пересоберите сайт.
6. Пройдите Проблемомер до результата — в таблице должна появиться новая строка.

Таблицу можно расшарить команде маркетинга на просмотр/редактирование. URL скрипта наружу не светите лишний раз (это и есть «секрет приёмника»).

## 7. Как размечать ссылки (чтобы видеть каналы)

К **базовому адресу** добавляйте параметры. Метка запоминается на вкладку и уходит в Метрику и в таблицу.

База:

`https://paulos99.github.io/multiframe-problemomer/`


| Куда ведёте              | Пример ссылки                                                   |
| ------------------------ | --------------------------------------------------------------- |
| Реклама Яндекс           | `…/?utm_source=yandex&utm_medium=cpc&utm_campaign=имя_кампании` |
| Официальный сайт StP     | `…/?utm_source=stp&utm_medium=site&utm_campaign=problemomer`    |
| Партнёр                  | `…/?ref=partner_название`                                       |
| Менеджер / QR на планшет | `…/?mgr=ivan`                                                   |
| Листовка / выставка      | `…/?utm_source=print&utm_medium=offline&utm_campaign=expo2026`  |


Правила простые:

- один партнёр = один стабильный `ref=…`;  
- один менеджер = один `mgr=…`;  
- в рекламе всегда заполняйте хотя бы `utm_source`, `utm_medium`, `utm_campaign`.

Иначе в отчётах всё свалится в «direct».

## 8. Что смотреть в отчётах



### В Метрике

- Воронка: старт → шаги → результат → клики CTA.  
- Какие кнопки «продают»: calc vs consult vs PDF vs share.  
- Откуда трафик (UTM + метки), если ссылки размечены.



### В таблице

- Сегменты спроса: тип дома, этап (новостройка / ремонт / живут), площадь, задача комнаты.  
- Какой комфорт «до» и «после» чаще встречается.  
- Срез по `channelLabel` (партнёр / менеджер / кампания).

## 9. Чеклист приёмки для маркетинга

- [ ] В GitHub Secrets заданы `VITE_YM_ID` и (если нужна таблица) `VITE_ANALYTICS_INGEST_URL`  
- [ ] После смены секретов прогнан Deploy  
- [ ] На сайте есть баннер cookies; после «Принять» в Метрике идут визиты  
- [ ] Созданы JS-цели с именами `pm_*`  
- [ ] Тестовый проход до результата → строка в таблице (если ingest включён)  
- [ ] Рекламные / партнёрские / менеджерские ссылки с UTM / `ref` / `mgr`  
- [ ] Команда знает: **лиды из Проблемомера не приходят** — только статистика

## 10. Кому что писать, если что-то не работает


| Симптом                               | Куда смотреть                                                             |
| ------------------------------------- | ------------------------------------------------------------------------- |
| Нет баннера cookies и нет Метрики     | Секрет `VITE_YM_ID` пустой или сайт не пересобран                         |
| Метрика есть, целей нет               | Цели в кабинете названы не так (`pm_…`) или не приняли cookies            |
| Таблица пустая                        | Нет `VITE_ANALYTICS_INGEST_URL`, скрипт не «для всех», сайт не пересобран |
| Всё «direct»                          | Ссылки без UTM / `ref` / `mgr`                                            |
| Нужен перенос на другой домен/хостинг | Передать хостеру два секрета и требование собирать с ними `dist`          |


Техническая шпаргалка для разработчиков: `[analytics.md](analytics.md)`.
