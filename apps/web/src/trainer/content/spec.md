# Тренажёр продаж для партнёров MultiFrame — техническое задание

Версия 2 · статус: к реализации · язык интерфейса: русский, без англицизмов.
Все данные лежат рядом с этим файлом: `objections.json`, `scenarios.json`, `quiz.json`, `scoring.json`. Проверка содержимого: `python3 tools/validate.py` (эталон необязательной автооценки свободного ответа — `tools/score_reference.py`).

**Что изменилось в версии 2.** Печатать ответы на телефоне долго и неудобно, а подбор слов по шаблонам давал ложные результаты (верный ответ простыми словами получал 0 из 6, а «не гарантируем тишину» помечалось нарушением). Поэтому основной режим теперь — **выбор ответа**: на каждую реплику клиента даны 4 готовых варианта, один верный. Оценка — по тому, угадан ли верный вариант с первой попытки, и по типам ошибок неверных вариантов. Свободный ответ остаётся необязательной практикой без оценки. Позже, вторым этапом, выбор целой фразы заменяется **сборкой ответа из блоков** (раздел 13).

## 1. Цель и границы

Дать каждому кабинету партнёра короткую, честную и измеримую тренировку: уметь ответить на возражение клиента фактами из обучающих видео, не обещать лишнего и договориться о следующем шаге.

Тренажёр живёт внутри существующего раздела «Обучение», работает без сети, ничего не создаёт в рабочих данных (сделки, клиенты, расчёты, продажи).

**Что входит:** три режима (быстрая отработка, ролевой сценарий, проверка знаний), выбор ответа вместо набора текста, оценка без нейросети, прогресс, интервальное повторение, банк возражений для панели «Что ответить клиенту».

**Что не входит (этап 2, отдельные задачи):** сборка ответа из блоков (проект данных — раздел 13); оценка нейросетью; командная статистика владельца на сервере; голосовой ввод; генерация новых сценариев.

### 1.1. Жёсткие правила содержания (нарушение = ошибка приёмки)

1. Источников фактов три, у каждого факта указан тип (`sourceType`).
   - `video` — расшифровки семи обучающих видео; основной источник. Каждый эталонный ответ и каждый вопрос викторины подтверждён короткой дословной цитатой; `validate.py` ищет её в расшифровке.
   - `web` — факт, которого нет в видео, но он проверен на надёжном сайте (производитель ООО «Стандартпласт»: stp.store, stp-multiframe.ru, stp-dom.ru; производитель материала; стандарт). Запись содержит `url`, `publisher`, `sourceKind` (manufacturer | retailer | material-producer | standard | independent), короткую дословную цитату `quote`, дату `accessed` и путь к снимку страницы `snapshot` (`sources/web/*.txt`). `validate.py` проверяет, что домен в списке, что цитата дословно есть в снимке, и что верный вариант ссылается на веб-факт только с атрибуцией («производитель указывает / пишет», «по словам производителей сырья», «считается»), если `attributionRequired`. Поле `use`: `claim` — факт можно говорить клиенту; `caveat` — только предостережение в пояснении (например, рекламная фраза, которую повторять нельзя); верный вариант на `caveat` не ссылается, неверный вариант не ссылается на веб-цитаты совсем.
   - `company` — заявление компании StP (решения владельца, Павел, 2026-10-29): группа горючести Г2 и класс КМ2; позиционирование материала как гипоаллергенного; SmartLock = замок шип-паз. Запись содержит `source` («StP / Павел, владелец»), `date`, `quote`, `note` и необязательный `mustSay` (слова, которые верный вариант обязан содержать, например Г2 и КМ2); ссылки и снимка нет, поэтому `validate.py` проверяет только наличие этих полей и что неверный вариант на заявление не ссылается. Документ-основание (протокол испытаний на горючесть) к заявлению пока не приложен: см. раздел 11, п. 14.
   - Данные розничных магазинов и общие сведения о материале (например, о вспененном полипропилене вообще) не выдаются за заключение по панели: они идут с атрибуцией или как `caveat`.
2. Нельзя использовать: «до 17 дБ» (на сайте производителя это «индекс звукоизоляции», но протокола испытаний нет), медицинские гарантии про аллергию («аллергии точно не будет», «не вызывает аллергии», «вылечит», «аллергикам точно подходит»; «у клиентов не будет аллергии» есть в рекламе на stp-multiframe.ru, но это не сертификат), цены и суммы, проценты «дешевле на N %», заработок партнёра, срок службы и пожизненную гарантию (общий текст про материалы StP на stp-dom.ru MultiFrame не называет). **Разрешено** с 2026-10-29: «гипоаллергенный» (позиционирование компании; с оговоркой «считается» и «по конкретной аллергии — к врачу»), «замок шип-паз (SmartLock)». Разрешено сказать, где указан гарантийный срок: «в документах и на маркировке» (stp.store, оферта п. 8.3). Запрещённые слова допустимы только в списках запрещённого (`forbiddenClaims`, `scoring.globalForbidden`, поле `commonMistake`, неверные варианты викторины).
3. Тишину не обещаем. Формулировка из видео: «ни одна система не делает квартиру абсолютно беззвучной; задача — повысить акустический комфорт и сделать шум менее раздражающим и заметным».
4. **Решение владельца 2026-10-29:** в содержимом тренажёра нет ссылок на наши испытания и нет конкретных цифр дБ из них (+1 дБ на потолке, +9 дБ на стене, −1/−3/−4 дБ у полистирола, одеяла и мембраны), нет ничего про стены (кабинет работает только с потолком). Вместо этого: общие утверждения (обычный полистирол на потолке часто ухудшает звукоизоляцию; акустическое одеяло или вата сами по себе проблему не решают) и ссылка на Проблемомер как на модель работы материала: эффект для комнаты клиента оценивает он, цифру в дБ для квартиры не называем и не обещаем. Закрытие разговора у менеджера: КП с оценкой эффективности из Проблемомера и количеством панелей с ценой из калькулятора плюс договорённость о следующем контакте; обещаний «втроём», сроков, потери площади и результатов испытаний в нём нет. Тест `contentRules.test.ts` проверяет это автоматически.
5. Об огне — формулировка из видео «Как продавать» (В1): «Система STP MultiFrame не поддерживает горения, не выделяет опасного черного дыма, не подвержена горячему каплепадению» (к ней добавлено «Ознакомьте клиента с сертификатами безопасности»; сертификаты в кабинете: раздел «Обучение» → Материалы; на QR-код в обучающем содержимом не ссылаемся) **и заявление компании (решение владельца, 2026-10-29, `sourceType: company`): «группа горючести Г2, класс КМ2»**. Говорить так: «группа горючести Г2, класс КМ2, не поддерживает горения». Нельзя: «негорючая», «НГ», «совсем не горит», «никакого дыма», любые другие группы и классы (Г1, Г3, Г4, КМ0, КМ1, КМ3), цитировать содержимое сертификата. Для объяснения ошибки «НГ» есть предостережение из закона 123-ФЗ, ст. 13 (НГ и Г1–Г4 — разные группы; Г2 — «умеренногорючие»). О пенопласте в видео сказано только, что изделия из экструдированного полистирола «подвержены горению и выделению канцерогенных вредных веществ».
6. О пыли — «нет сильного пыления», а не «пыли нет совсем». Об аллергии — с 2026-10-29 можно говорить «материал гипоаллергенный: вспененный полипропилен и вязкоэластичная пена считаются гипоаллергенными, химически инертны, не пылят» (позиционирование компании, `company`, плюс веб-источники, см. 11.20); отсутствие пыли и вредных частиц особенно важно для семей с детьми и аллергиков (видео); производитель указывает, что панели не содержат вредных веществ и не пылят; EPP по словам производителей сырья вспенивают без химических вспенивающих агентов. Всегда с оговоркой «считается» и «по конкретной аллергии — к врачу». Нельзя медицинские гарантии: «аллергии точно не будет», «не вызывает аллергии», «безопасно аллергикам», «вылечит». Наполнитель панели — Eco Foam у Wave, ППУ Full Touch у Flat; что он вязкоэластичная пена, подтверждает заявление компании, на страницах производителя этого слова нет.
7. Тексты для пользователя — на русском. Исключения: названия продукта (MultiFrame, Wave, Flat), «SmartLock» только в виде «замок шип-паз (SmartLock)», «дБ». Замок везде называется **«шип-паз»** (в расшифровках видео распознано как «SHIPPASS» / «SHIP PASS»: такие написания остаются только внутри дословных видеоцитат). Ключи JSON и идентификаторы — латиницей.

### 2.1. Возражение (`objections.json → objections[]`)

```
id                     строка, например "obj-price-expensive"
type                   price | competitor | trust | expectation | technical | safety | installation | timing | need | space | decision_maker
refusalReasonKey       ключ из refusalReasons (см. 2.5)
roles                  [owner | manager | measurer | crew | stp_admin]
difficulty             1–3
clientPhrasing[]       2–3 способа, как клиент говорит это; в тренажёре выбирается один (звучит как живой человек, без книжных оборотов)
pushback               вторая реплика клиента («дожим»); тренируемый отвечает ещё раз
choices                { beat1: Choice, beat2: Choice }   — выбор ответа на реплику 1 и на реплику 2 (см. ниже)
referenceAnswer        эталон на первую реплику (для разбора, для свободной практики)
pushbackReferenceAnswer эталон на повтор
requiredPoints[]       { id, ideaId, text, anyOf[], beats: [1] | [2] | [1,2], critical, quoteIds[] }  — подсказки, не оценка (см. «Пункты» ниже)
forbiddenClaims[]      { id, text, patternsRef? }  id вида "g-…" — глобальное правило из scoring.json; "l-…" — местное
sourceQuotes[]         { id: "q1", sourceType: video, videoCode, quote, appliesTo: answer|pushback|both }
                       { id: "w1", sourceType: web, url, publisher, sourceKind, quote, snapshot, accessed, appliesTo, use: claim|caveat, attributionRequired?, note? }
                       { id: "c1", sourceType: company, source: "StP / Павел, владелец", date: "2026-10-29", quote, appliesTo, use: claim, note, mustSay? }
openIssues[]           необязательно: { id, text } — нерешённый вопрос к методологу (сейчас в данных не используется; открытые вопросы — в разделе 11)
commonMistake          типичная ошибка, одной фразой
panel                  { title, shortAnswer, keyFact, showMaterial[{videoCode,title,hint}], priority 1–4 } для панели «Что ответить клиенту»
```

**Выбор ответа (`choices.beat1`, `choices.beat2`).**

```
Choice  { mode: "single", options[4] }
Option  { id, text, correct, errorType | null, violates | null, explanation, quoteIds[] }
```

- Ровно один вариант `correct: true`, остальные три — неверные. Варианта «всё перечисленное» нет.
- `errorType` неверного варианта: `false_promise` (обещание или выдуманный факт), `pressure` (давление, спор, раздражение), `vague` (расплывчато: без факта и пользы), `ignores_concern` (мимо заботы клиента). Каждый выбор содержит ловушку на честность (`false_promise`) там, где она естественна; всего в банке: `false_promise` 85, `pressure` 62, `vague` 58, `ignores_concern` 11.
- `violates` — критерий, с которого снимается балл при неверном первом выборе: по умолчанию `false_promise → honesty`, `pressure → listening`, `ignores_concern → objection`, `vague → value`; у отдельных вариантов задано иначе (например, расплывчатый ответ без вопроса — `discovery`, без срока — `nextstep`). Распределение в банке: honesty 85, listening 62, value 49, objection 11, nextstep 7, discovery 2.
- `explanation` — одна-две фразы по-русски. У неверного варианта — что здесь не так и как лучше; у верного — почему он верный, с дословным словом из видео. Верный вариант всегда подтверждён цитатами через `quoteIds`.
- Тексты вариантов звучат как живая речь партнёра (без «Логично. Вы это без нажима объясняете» и подобных книжных заготовок; проверка по списку оборотов в `validate.py`).
- **Верный вариант не должен выделяться.** Он не обязан быть самым длинным и не стоит всегда на одном месте. `validate.py` проверяет: верный самый длинный не более чем в 45 % выборов (сейчас 8 из 72), среднее отношение длины верного к неверным 0,8–1,25, одна позиция верного не более 45 % (сейчас: позиция 1 — 14, 2 — 17, 3 — 22, 4 — 19). В хранении варианты уже перемешаны детерминированно; приложение при показе перемешивает заново, но привязывает ответ к `id`, а не к номеру.
- Условия для текста: в верном ответе нет запрещённых утверждений (`forbiddenClaims`, глобальный список), отрицания проверяются по клаузам, а не по окну слов (5.3); цифры только из цитат; об огне — только дословная формулировка из видео (1.1, п. 5).

**Пункты (`requiredPoints`, `ideas`) — подсказки, а не оценка.** Поле `requiredPoints` перечисляет, «что содержит хороший ответ». В режиме выбора оно ничего не оценивает: показывается в разборе как список идей с цитатами и служит проверкой данных. Правила:
- **Одна идея — один пункт.** Каждая идея описана один раз в `ideas[]` (`id`, `text`, `anyOf[]`); пункты возражений ссылаются на неё по `ideaId` и повторяют её текст и шаблоны без отличий. Внутри возражения идея не повторяется: пункт, ожидаемый и в первой, и во второй реплике, один (`beats: [1, 2]`). `validate.py` отклоняет расхождения, повторы и одинаковые тексты у разных идей. В версии 2 слито 84 дубля: 199 исходных пунктов → 115 идей (179 пунктов в 36 возражениях).
- **Сопоставление в свободной практике — по всему диалогу.** Пункт ищется в обоих ответах вместе, а не только в «своей» реплике (так уходит ошибка «сказано в первой реплике, засчитано только во второй»); `beats` показывает, где это обычно ждут. Результат — подсветка «это вы сказали», а не балл.
- `anyOf` — список регулярных выражений. Пункт засчитан для подсказки, если совпали не менее `minMatches` (по умолчанию 1) разных выражений. Критичный пункт показывается первым.
- Выражения записаны в нижнем регистре, без «ё». Без `\b`, `\w`, `\W` (в JavaScript они не работают с кириллицей) и без встроенных флагов. Перед проверкой текст нормализуется (5.1). Основа слова, а не форма: «горени» ловит «горения» и «горение», «сертификат» ловит «сертификатам».
- В `objections.json` верхнего уровня задано `requiredPointsRole: "hint"`; `validate.py` проверяет это значение.

Остальные правила:
- `forbiddenClaims[].id` с префиксом `g-` ссылается на `scoring.globalForbidden`; с префиксом `l-` — местное правило без шаблонов (только для самооценки), если нет записи в `scoring.localForbiddenPatterns`.
- Одна цитата может подтверждать несколько пунктов и вариантов; ссылки идут через `quoteIds`.

### 2.2. Сценарий (`scenarios.json → scenarios[]`)

```
id, title, roles[], callType, difficulty 1–3, estimatedMinutes
persona          { name, age, description, mood, hiddenNeed, knowsAbout }
goal             цель тренируемого (одна фраза)
setup            вводная для экрана «Ситуация»
steps[]          { id, objectionId, clientPhrasingIndex, beats: 2, clientLines[2], coachHint, afterPass, afterFail, choices }
closing          { clientLine, requiresNextStep: true, choices, afterCorrect, afterWrong, goodExamples[] }
successCriteria[]{ id, kind: firstTryCorrect | noFalsePromise | nextStepChoice, text }
practiceFocus[]  задачи для необязательного свободного ответа (без оценки)
tags[]
```

- Шаг = возражение из банка. `clientLines[2]` — две реплики клиента в голосе этого персонажа (первая и повтор): именно они показываются в сценарии; `clientPhrasingIndex` и `pushback` банка остаются для быстрой отработки и панели.
- `choices` шага — `{ beat1, beat2 }` той же формы, что в банке. Варианты — копии вариантов возражения (`sourceOptionId` указывает на оригинал; `validate.py` проверяет, что копия не отличается по тексту, верности и типу ошибки); порядок перемешан отдельно для каждого шага.
- `closing.choices` — выбор следующего шага из 4 вариантов, один верный: действие, срок и кто делает. Неверные: расплывчатое «созвонимся потом», давление «оформим сегодня» и обещание без основания; у всех `violates: "nextstep"`. `goodExamples` = текст верного варианта.
- После двух выборов шага показывается `afterPass` (оба выбора верны с первой попытки) или `afterFail` (был неверный первый выбор). Реплики `afterPass`/`afterFail`/`afterCorrect`/`afterWrong` — речь живого клиента, продуктовых фактов в них нет.
- `successCriteria` отмечаются автоматически: `firstTryCorrect` — верный выбор с первой попытки в каждой реплике шага; `noFalsePromise` — ни разу не выбран вариант с `errorType: false_promise`; `nextStepChoice` — в конце выбран верный следующий шаг. Прежние ручные критерии перенесены в `practiceFocus`.

### 2.3. Вопрос викторины (`quiz.json → questions[]`)

```
id, topic, difficulty 1–3, type: "single" | "multi"
question, options[{id, text}], correctOptionIds[], explanation
sourceQuotes[]   { id, videoCode, quote }
isTrap           true — вопрос про типичную ошибку (чужая цифра, «негорючий», «тишина» и т. п.)
roles[], relatedObjectionIds[]
```
Порядок вариантов уже перемешан, при показе перемешиваем заново (с зерном от id вопроса и номера попытки). Вопросы-ловушки при ошибке показывают связанное возражение (`relatedObjectionIds`) как ссылку «Потренировать».

### 2.4. Оценка (`scoring.json`)

Описана в разделе 5 (выбор ответа — 5.0; шаблоны — только для необязательной свободной практики). Ключевые поля: `criteria[]`, `modes` (в том числе `choice`), `choiceMode` (правила выбора, критерии из нарушений, `requiredPointsPolicy`), `coverageToScore`, `capIfCriticalMissing`, `honestyGate`, `passThresholds`, `negationWords`, `globalForbidden[]`, `ackStarters`, `openQuestionStarters`, `valueLinkPattern`, `nextStep{action,time,who}`, `srs`.

## 3. Режимы

### 3.1. Быстрая отработка («Отработать возражение»)

Для коротких подходов по 2–3 минуты, одной рукой на телефоне: печатать ничего не нужно.

1. Пользователь открывает «Обучение → Тренажёр продаж → Быстрая отработка». Колода собирается из возражений, подходящих его роли (`objection.roles ∋ role`); порядок — сначала просроченные по расписанию повторений, потом новые, потом остальные; в подходе 5 возражений (изменяется в «Настройках подхода», маленькая форма в модальном окне по центру).
2. **Реплика 1.** Показываем реплику клиента (одну из `clientPhrasing`, чередуем) и четыре варианта ответа крупными кнопками (`choices.beat1`; порядок перемешан при показе). Одно нажатие — выбор.
3. **Проверка выбора.**
   - Верный вариант: подсвечивается, показывается `explanation` с дословной цитатой из видео, кнопка «Дальше».
   - Неверный вариант: помечается и блокируется, показывается его `explanation` (что не так и как лучше), остальные варианты доступны для нового выбора. Повтор не ограничен, но реплика уже считается «не с первой попытки».
4. **Реплика 2.** Показываем `pushback` и `choices.beat2`, выбор проходит так же.
5. **Разбор.** Страница: результат «верно с первой попытки: N из 2»; оба верных варианта (и эталоны `referenceAnswer`, `pushbackReferenceAnswer` для сравнения); цитаты из видео с кнопкой «Открыть видео»; типичная ошибка; список «Что содержит хороший ответ» (`requiredPoints`, критичные первыми, статично — без сопоставления с выбором); ошибки, выбранные в этот раз, с их типами.
6. Необязательно: кнопка «Ответить своими словами» — свободный ответ (без оценки; можно отметить «это я сказал» по подсказкам). Оценку и баллы не меняет.
7. Кнопки: «Следующее возражение», «Повторить это», «Закончить». После последней карточки — итог подхода: доля верных с первой попытки, критерии из нарушений, что повторить.

### 3.2. Ролевой сценарий («Разговор с клиентом»)

Длительность 6–8 минут. Экран «Ситуация» (персона, цель, подсказка) → шаги → заключительный выбор → итог.

1. Экран «Ситуация»: имя и описание клиента, цель, роль пользователя, что нужно получить («конкретный следующий шаг»). Кнопка «Начать разговор».
2. Для каждого шага: реплика клиента (`clientLines[0]`) → выбор из 4 вариантов (`choices.beat1`) → повтор (`clientLines[1]`) → выбор из 4 (`choices.beat2`) → реплика `afterPass` (оба выбора верны с первой попытки) или `afterFail` (иначе). Неверный выбор показывает пояснение и даёт выбрать снова; разговор продолжается только после верного выбора. Подсказка `coachHint` доступна по кнопке «Подсказка»; использованная подсказка отмечается в попытке (`usedHint`) и не снимает баллов.
3. Заключительная реплика (`closing.clientLine`): выбор следующего шага из 4 вариантов (`closing.choices`): действие, срок, кто делает. Верный — `afterCorrect`, неверный — `afterWrong` и новый выбор.
4. Итог: доля верных с первой попытки по всем выборам сценария (шаги и заключительный), критерии сценария (`successCriteria`: `firstTryCorrect`, `noFalsePromise`, `nextStepChoice` — отмечаются автоматически), критерии из нарушений (5.0), разбор по шагам с цитатами, верный следующий шаг (`goodExamples`), задачи для свободной практики (`practiceFocus`).
5. Сценарий можно прервать, прогресс шага сохраняется как черновик на устройстве (до 7 дней).

### 3.3. Проверка знаний («Викторина»)

1. Выбор: «Быстрая (10 вопросов)», «По теме», «Ловушки» (только `isTrap`), «Повторить» (по расписанию). Вопросы подбираются по роли пользователя.
2. Один вопрос на экране; после ответа сразу показываем верный вариант, пояснение и цитату из видео; затем «Дальше».
3. Итог: процент верных, разбивка по темам, список ошибок со ссылками на связанные возражения (`relatedObjectionIds`) и кнопкой «Потренировать».
4. Критерий «Честность» в викторине = доля верных ответов на вопросы-ловушки (≥ 80 % = 5, 60–79 % = 4, 40–59 % = 3, 20–39 % = 2, меньше = 1; если ловушек в подходе нет — критерий не считается).

## 4. Экраны и потоки по ролям

Размещение: раздел «Обучение» (внутри него отдельная карточка «Тренажёр продаж»). Настольная версия — левое меню; телефон — меню-«бургер». Все содержательные экраны открываются страницами; маленькие формы (настройки подхода, фильтр, подтверждение сброса прогресса, пометка к самооценке) — окном по центру.

**Маршруты (страницы):**
- `Обучение → Тренажёр продаж` — главная: «Сегодня» (что повторить, подход на 5 минут), три плитки режимов, «Мой прогресс».
- `…/отработка` и `…/отработка/:id` — быстрая отработка и разбор карточки.
- `…/сценарии`, `…/сценарии/:id` (ситуация), `…/сценарии/:id/разговор`, `…/сценарии/:id/итог`.
- `…/викторина`, `…/викторина/итог`.
- `…/прогресс` — прогресс по критериям, темам, причинам отказа, история попыток.
- `…/банк-возражений` — справочник: список возражений с фильтром по причине отказа; карточка показывает `panel`, эталоны и цитаты.

| Роль | Основной путь | Что видит |
|---|---|---|
| Владелец партнёра | «Сегодня» → быстрая отработка (цена, конкуренты, доверие, решение) → сценарии «Владелец убеждает мастера», «Скептик-инженер», «Клиент говорит “дорого”» | всё содержимое для `owner`; «Мой прогресс». Командная статистика — этап 2 |
| Менеджер | «Сегодня» → быстрая отработка → сценарии звонков («Первый звонок», «После коммерческого предложения», «Повторный звонок», «Спутник решения») → викторина «Как продавать» | возражения и сценарии для `manager`; банк возражений с фильтром по причине отказа |
| Замерщик | быстрая отработка по теме «Высота и площадь», «Провода», «Честность по потолку» → сценарий «Замерщик на объекте» → викторина «Монтаж» и «Высота и площадь» | возражения и вопросы для `measurer` |
| Монтажник (бригада) | быстрая отработка («На чём держится», «Как резать», «Качество монтажа», «Безопасность») → сценарий «Монтажник на объекте» → викторина «Монтаж» | возражения и вопросы для `crew` |
| Администратор СТП | как менеджер + просмотр всего содержимого, версии контента и результатов проверки; кнопка «Скопировать цитату» | всё |

Правила доступа: роль берётся из учётной записи; пользователь может переключить фильтр «Показать все роли» (маленькая форма), но прогресс считается по его роли. Если у роли нет сценариев (в текущем наборе есть у всех пяти), показывается сообщение с предложением быстрой отработки.

**Состояния экранов (для каждого):** загрузка, пусто, ошибка чтения содержимого («Не удалось загрузить тренажёр. Содержимое сохранено на устройстве — попробуйте обновить страницу»), нет сети (тренажёр работает; значок «Без сети» только у отправки результатов), успех.

## 5. Оценка без нейросети

### 5.0. Оценка в режиме выбора (основной режим)

Описана в `scoring.json → choiceMode`. Нейросеть и шаблоны слов не участвуют.

1. **Основной результат — «верно с первой попытки».** Доля реплик, где первый выбор верный: число верных с первого раза / число реплик. Для быстрой отработки реплик две на возражение; для сценария — реплики шагов и заключительный выбор вместе.
2. **Критерии из нарушений.** Каждый неверный первый выбор снимает балл с критерия из `violates` этого варианта: критерий стартует с 5, каждое нарушение — минус 1,5, не ниже 1. Критерий, по которому в сыгранном материале не было ни одного варианта с таким `violates`, показывается как «не оценивалось», а не как 5. Итог (0–5) = Σ(вес × оценка) / Σ(веса оценённых критериев). Из-за малого числа вариантов с `discovery` (2 на банк) этот критерий почти всегда будет «не оценивалось» — это известное ограничение (11.14), пока в варианты не добавятся вопросы клиенту.
3. **Порог «засчитано».** Быстрая отработка: ≥ 75 % верных с первой попытки. Сценарий: ≥ 75 % и ни одного выбора `false_promise`. Уровни по среднему первой попытки: «Начинающий» (< 75 %), «Уверенный» (≥ 75 %), «Мастер» (≥ 90 %). Значения предварительные, уточнить по пилоту.
4. **Честность.** Выбор варианта `false_promise` в сценарии лишает отметки «засчитано» и объясняется пользователю цитатой и верной формулировкой (на 5.4 это замещает `honestyGate` для режима выбора).
5. **Повторение.** Возражение идёт в коробку +1, если оба выбора реплик верны с первой попытки, иначе коробка = 1 (раздел 6).
6. **Пункты `requiredPoints` не участвуют в оценке.** Это подсказки разбора («что содержит хороший ответ»). Баллы режима выбора считаются только по первому выбору и тегу `violates`. Верность вариантов гарантирует автор данных и `validate.py` (запрещённые утверждения, дословные цитаты, баланс длины и позиции).

Свободный ответ (необязательно, без оценки) показывает эталон и подсветку «это вы сказали» по пунктам; он ищет пункты в обоих ответах вместе.

### 5.1. Нормализация

Нужна только для необязательной проверки свободного текста и для `validate.py`. Перед проверкой: нижний регистр, «ё» → «е», кавычки «»"“” → пробел, повторные пробелы → один. Все шаблоны в JSON уже написаны с учётом этого. Предложения делятся по `. ! ? ;` и переводу строки.

### 5.2. Критерии

Шесть критериев по шкале 1–5; якоря для самооценки — в `scoring.criteria[].anchors`. Критерий «доля речи» для текстового тренажёра неприменим, вместо него «Выяснение потребности» и «Слышу клиента».

| id | Название | Вес | Режимы | Откуда оценка в режиме выбора |
|---|---|---|---|---|
| discovery | Выяснение потребности | 0,15 | отработка, сценарий | `violates: discovery` |
| listening | Слышу клиента | 0,15 | отработка, сценарий | `violates: listening` (давление, спор) |
| objection | Ответ на возражение | 0,25 | отработка, сценарий | `violates: objection` (мимо заботы) |
| value | Ценность для клиента | 0,15 | отработка, сценарий | `violates: value` (расплывчато) |
| honesty | Честность утверждений | 0,20 | все | `violates: honesty` (ложное обещание, выдуманный факт) |
| nextstep | Следующий шаг | 0,10 | сценарий | неверный следующий шаг в `closing` |

Итог = Σ(вес × оценка) / Σ(веса оценённых критериев): неприменимые и «не оценивавшиеся» критерии исключаются, остальные веса пересчитываются в сумму 1.

### 5.3. Автооценка свободного ответа (только необязательная практика; эталон: `tools/score_reference.py`)

В версии 2 не влияет на результат и баллов не выдаёт; остаётся для свободной практики как подсказка и как проверка эталонов в `validate.py`. Для каждой из двух реплик считается отдельно; затем объединяется (`score_step`); пункты ищутся в обоих ответах вместе.

1. **Ответ на возражение.** Для каждого пункта: засчитан, если совпали ≥ `minMatches` выражений из `anyOf`. Охват = Σ(вес засчитанных) / Σ(веса всех), критичный = 2. Оценка по таблице `coverageToScore`: [0 → 1], [0,2 → 2], [0,4 → 3], [0,6 → 4], [0,8 → 5]. Если пропущен критичный пункт — не выше `capIfCriticalMissing` (3).
2. **Честность.** Для всех предложений ответа ищем совпадения глобальных и местных запрещённых шаблонов. Отрицание проверяется **по клаузам**, а не по окну слов: предложение делится на отрезки по «но / зато / однако», отрезок — на клаузы по `, ; : — – а`. Совпадение **не считается**, если в той же клаузе стоит слово из `negationWords` («не обещаем тишину», «абсолютной тишины мы вам не гарантируем», «не могу гарантировать») при `negationAware = true`, или клауза совпала с `exceptIfSentenceMatches` (например, «не поддерживает горения»). Утверждение после «но» оценивается отдельно: «Я не обещаю идеал, но полная тишина у вас будет» — нарушение. Прежнее окно в 6 слов перед совпадением отменено: оно давало ложные нарушения на порядке слов «тишины мы вам не гарантируем». Одно критическое нарушение — оценка 1. Каждое предупреждение (`warn`) — минус 1 от 5, не ниже 3.
3. **Выяснение потребности.** Нет вопросительного знака — 1; есть вопрос, но без открытого вопросительного слова — 3; есть открытый вопрос — 5.
4. **Слышу клиента.** 1 + 2, если ответ в первых 120 знаках начинается с признания (`ackStarters`) + 2, если повторены слова клиента.
5. **Ценность.** Нет засчитанных пунктов с цитатой — 1; есть факты, но нет обращения к клиенту — 3; факты + обращение — 4; два и более факта + обращение — 5.
6. **Следующий шаг.** Нет действия — 1; есть действие — 3; действие и срок — 4; действие, срок и исполнитель — 5.

### 5.4. Ограничение по честности (`honestyGate`)

В режиме выбора — п. 5.0.4. Для свободной практики с автооценкой: если «Честность» ≤ 2, итог не выше 2,4.

### 5.5. Самооценка и защита от подбора слов

Относятся только к свободной практике и необязательны. В режиме выбора подбора слов нет: неверный вариант нельзя угадать «по ключевым словам», его ловушка объяснена в `explanation`.

### 5.6. Необязательный этап: нейросеть (позже)

Если включён и есть сеть, свободный ответ, эталон, `requiredPoints` и якоря отправляются на оценку; результат хранится как `llmScores` и в итог не подмешивается без подтверждения пользователя. Нейросеть не должна добавлять факты вне `sourceQuotes`. Без сети работает только выбор ответа.

## 6. Прогресс и интервальное повторение

- Единица повторения — возражение или вопрос (`objections.id`, `quiz.id`). Сценарии не повторяются по расписанию, но их шаги обновляют карточки возражений.
- Коробки 1–5 с интервалами 0 / 1 / 3 / 7 / 21 дней (`scoring.srs`). «Засчитано» — коробка + 1 (не выше 5); «не засчитано» — коробка = 1. `nextDueAt = lastAt + интервал[коробка]`.
- Очередь «Сегодня»: карточки с `nextDueAt ≤ сейчас`, сверху низкая коробка и большая просрочка; лимит `srs.dailyLimit` (10) в день; новые карточки добавляются, если очередь короче лимита.
- «Мой прогресс»: средний балл по каждому из шести критериев (последние 10 попыток); освоено / в работе / не начато по темам и по причинам отказа (карточка «освоена» в коробке ≥ 4); серия дней (без наказания за пропуск); список слабых мест (критерии < 3,5, часто пропускаемые пункты `missedPointIds`).
- Сброс прогресса — в маленьком окне подтверждения; удаляет данные только на этом устройстве.

## 7. Повторное использование банка возражений: панель «Что ответить клиенту»

Панель в карточке проекта менеджера читает тот же `objections.json`, ничего не копируя:

1. Менеджер выбирает причину отказа клиента (`refusalReasonKey`).
2. Панель показывает возражения с этой причиной по `panel.priority` (1 — самые частые). Для каждого: `panel.title`, `panel.shortAnswer`, `panel.keyFact`, ссылки на материалы (`panel.showMaterial`) и кнопка «Потренировать» (открывает карточку быстрой отработки).
3. Короткие ответы (`panel.shortAnswer`) только из подтверждённых фактов; запрещённые утверждения (`forbiddenClaims`) показываются в свёрнутом блоке «Чего не говорить».
4. Использование панели — это не попытка тренировки и не меняет коробки.
5. Кнопка «Скопировать ответ» копирует `panel.shortAnswer` в буфер; текст можно править перед отправкой клиенту (менеджер отвечает за итог).

## 8. Работа без сети и синхронизация

- Четыре файла JSON и реестр видео кладутся в предзагрузку сервисного работника с версией; обновление содержимого — по версии `contentVersion`, с показом «Доступны новые вопросы» (без прерывания текущего подхода).
- Все попытки пишутся сразу в IndexedDB; `synced = false`. При появлении сети — отправка очередью (идемпотентно по `attempt.id`). Если на сервере нет конечной точки, этап 1 работает полностью локально, а очередь накапливается и отправляется после появления конечной точки.
- Видео не обязательны в офлайне: если ролик недоступен, показываем цитату и название ролика.
- Попытка тренировки **никогда** не создаёт и не изменяет сделки, клиентов, проекты, расчёты, продажи или события учёта. Поле `context: "training"` обязательно.
- Данные на устройстве привязаны к `userId`; при выходе из кабинета другого пользователя прогресс не виден.

## 9. Доступность и язык

- Весь текст интерфейса — по-русски, без англицизмов: «подход», «разбор», «возражение», «следующий шаг», «повторить», «ловушка», «без сети». Не использовать: «фидбек», «кейс», «дедлайн», «скрипт», «чек-лист», «онлайн/офлайн», «челлендж», «стрик».
- Контраст, размер шрифта ≥ 16 px на телефоне, поле ввода растягивается, клавиатура не закрывает кнопку «Ответить».
- Все действия доступны с клавиатуры; фокус виден; подсветка в разборе не опирается только на цвет (значки ✔ и ✖ и слова «названо / не названо»).
- Экраны работают на ширине 360 px и на настольных экранах; на настольном — две колонки: слева разговор, справа подсказки и цитаты.

## 10. Критерии приёмки

Содержимое:
1. `python3 tools/validate.py` завершается кодом 0: все JSON читаются, нет ошибок, нет предупреждений.
2. В `objections.json` 25–40 возражений (сейчас 36), у каждого ≥ 2 формулировок клиента, повтор, два эталона, пункты, запрещённые утверждения и цитаты; видеоцитаты дословно есть в расшифровках, веб-цитаты — в снимках страниц `sources/web/` (сейчас 186 видеоцитат и 13 веб-цитат: 9 `claim`, 4 `caveat`).
3. Основные пять причин отказа покрыты возражениями.
4. В `quiz.json` ≥ 30 вопросов (сейчас 51), у каждого цитата; ≥ 10 % вопросов-ловушек.
5. В `scenarios.json` 8–12 сценариев (сейчас 12), охвачены все пять ролей; в каждом есть критерий конкретного следующего шага.
6. Запрещённые слова и цифры (раздел 1.1) не встречаются в эталонах, ответах панели, вопросах, сценариях.

## 11. Известные пробелы и неоднозначности (решить до запуска или принять)

1. **Цены и деньги.** В видео есть цены, проценты экономии и заработок партнёра, но они не сверены и частично противоречат друг другу (например, «на 40 % ниже» в таблице, «на 20–30 % дороже» в тексте, разные цифры за м² в разных местах). По указанию они исключены. Возражения о цене отвечают без цифр и предлагают свой расчёт партнёра. Если нужны цифры, нужен подтверждённый прайс отдельным файлом.
2. **Испытание измеряло воздушный шум.** Для шагов (ударный шум) цифр нет; в ответах про шаги говорится только, что система помогает снизить такой шум и что тишину не обещаем.
3. **Потолок при исходном уровне 38–45 дБ** не измерялся. В ответах: «у нас замера нет; специалисты по акустике прогнозируют несколько дБ как очень хороший результат» — это цитата из видео об ожиданиях, а не измерение.
4. **Срок службы, гарантия, ресурс** в видео не названы и на страницах MultiFrame не найдены; в ответах сказано «не называем» и «срок указан в документах и на маркировке» (оферта stp.store, п. 8.3). «Пожизненная гарантия» есть на stp-dom.ru для материалов StP вообще: привязывать её к MultiFrame нельзя без подтверждения производителя.
5. **Противоречие в видео про стену (В6):** «плотное примыкание ко всем поверхностям» и «избегайте плотного соприкосновения каркаса с поверхностью». Возможна ошибка распознавания; в содержимое не включено.
6. **Видео В7** — десять секунд без речи (автоматическая расшифровка «Слышен звук» ненадёжна). Файла звука в расшифровках нет: для аудио-демо нужен исходный ролик; тренажёр лишь ссылается на него (`showMaterial`).
7. **Нет отдельных видео** для замерщика (порядок замера), для бригады (приёмка, акт), для администратора СТП. Сценарии этих ролей составлены только из фактов монтажа и продаж; уточнения от СТП улучшат их.
8. **Нет видео про «Решает не он один» и про «Тихие соседи».** Ответы построены из общих положений видео (консультация без давления, материалы для передачи, двусторонний эффект, акустический комфорт) (для «Решает не один» это сказано в `panel.keyFact`).
9. **Таблица отработки возражений** из видео «Как продавать» в расшифровках отсутствует; если её дать, банк можно сверить.
10. **Авторский текст.** Реплики клиента, `pushback`, персоны, `afterPass/afterFail` и пояснения написаны для тренажёра; они не содержат утверждений о продукте сверх цитат. Эталоны ответов и пункты опираются только на цитаты.
11. **Пороги и веса предварительные.** Нужен пилот на 10–15 пользователях, чтобы откалибровать шаблоны (`anyOf`), пороги и веса; шаблоны подобраны под типичные формулировки и могут пропускать корректные ответы другими словами — поэтому самооценка обязательна.
12. **Названия:** «MultiFrame», «Wave», «Flat»; замок — «шип-паз» (решение владельца, 2026-10-29; в расшифровке распознан как «SHIPPASS» / «SHIP PASS»). В интерфейсе писать «шип-паз»; «SmartLock» допустимо только как «замок шип-паз (SmartLock)». Решено, вопрос закрыт.
13. **Размер:** `objections.json` около 530 КБ (около 86 КБ в сжатом виде, `gzip`); при необходимости можно загружать выбор, пункты и цитаты отдельно от формулировок.
14. **Горючесть панели (открытый вопрос — документы и розница).** Владелец заявил (2026-10-29): группа горючести Г2, класс КМ2; в ответах это говорится как заявление компании. Открыто: (а) приложить протокол испытаний / сертификат на Г2 и КМ2 (сейчас заявление без документа-основания); (б) **в карточке розничного магазина «Створка Маркет» (панель MultiFrame Flat, market.stworka.com) указано «Группа горючести: Г4» — это расходится с заявленной Г2 и должно быть исправлено у ритейлера**; в содержимое тренажёра эта карточка не входит. Нужны также проверка, что Г2 и КМ2 относятся ко всем вариантам панели (Wave и Flat).
15. **Заявленная цифра «до 17 дБ»** есть на карточках stp.store («Индекс звукоизоляции до 17 дБ»), но протокола испытаний ΔRw/ΔLw нет. Не используется; в обучении цифр дБ нет вообще: эффект оценивает Проблемомер.
16. **Название замка (закрыто).** Владелец: SmartLock — фирменное название замка шип-паз у производителя, это одно и то же. Нюанс: на stp.store «шип-паз» описывает соединение панелей, а SmartLock — систему крепления; при расхождении с технической документацией уточнить у СТП.
17. **Веб-факты — заявления производителя.** Они могут измениться; снимки страниц сохранены (дата 2026-10-29). Свойства EPP «вообще» (RUCH, КНАУФ ПЕНОПЛАСТ) не равны свойствам панели: наполнитель панели — Eco Foam или ППУ Full Touch.
18. **Режим выбора плохо размечает «Выяснение потребности» (discovery):** критерий почти не оценивается; для него остаётся практика со свободным ответом или будущая сборка из блоков.
19. **Шаги сценариев используют копии выборов возражений** (`sourceOptionId`), поэтому один и тот же выбор встречается и в быстрой отработке, и в сценарии. Это сознательно (единый источник правды); при смене текста обновлять оба места пересборкой (`_build/build.py`).
20. **«Гипоаллергенный»: что подтверждено.** Слово разрешено как позиционирование компании. Проверка в сети (2026-10-29): независимого авторитетного источника (стандарт, медицинская организация), который буквально называл бы вспененный полипропилен «гипоаллергенным», не найдено; так его называют только поставщики изделий из EPP (Qingdao Maifeng: «Non-toxic and hypoallergenic»), а производитель КНАУФ ПЕНОПЛАСТ пишет о безопасности и отсутствии опасных веществ. О вязкоэластичной пене (memory foam) независимое издание Sleep Foundation пишет, что она «считается устойчивой к аллергенам» (allergen-resistant), а магазин матрасов Sleep World напоминает, что «гипоаллергенный» не абсолютная гарантия. Поэтому в ответах — «считается гипоаллергенным», без «точно» и «не вызывает». Что наполнитель панели — именно вязкоэластичная пена, подтверждает только заявление компании; на страницах производителя написано Eco Foam / ППУ Full Touch.

## 12. Сопровождение содержимого

- Любое новое утверждение добавляется только вместе с цитатой: из видео или с проверенного сайта (раздел 1.1, п. 1); для веб-факта сохраняется снимок страницы и ссылка. Запрос на изменение проходит `tools/validate.py`.

- Шаблоны `anyOf` пополнять по журналу пропущенных пунктов из пилота (поле `missedPointIds` с `selfScores`, где пользователь поставил высокую оценку, а автооценка низкую).

## 13. Позже: сборка ответа из блоков (проект данных, этап 2)

Решение Павла: сначала выбор ответа (сделано), затем сборка. Здесь только проект, без реализации.

**Идея.** Ответ клиенту собирается из 3–4 коротких блоков по порядку: услышать → факт → следующий шаг (+ необязательный блок «уточнить»). Пользователь выбирает по одному блоку из 3–4 вариантов на каждом шаге. Ничего не печатается.

**Опора на существующие данные.**
- `ideas[]` — каталог идей (115). Блок «факт» = одна идея, у неё уже есть текст и список шаблонов; блок «услышать» и «следующий шаг» — отдельные типы блоков.
- `requiredPoints` — подсказка «что должно быть в ответе»: тип блока и обязательные идеи берутся из них (`critical` — обязательный блок).
- `sourceQuotes` и веб-цитаты — у каждого блока `quoteIds`; веб-факт — только с атрибуцией (поле `attributionRequired`).
- Неверные блоки получают те же `errorType` и `violates` (false_promise, pressure, vague, ignores_concern), так что оценка и критерии не меняются.

**Схема (набросок).**
```
blocks[]   { id, kind: hear|fact|next|clarify, ideaId?, text, correct, errorType, violates, explanation, quoteIds[], compatibleWith[] }
assembly   { objectionId, beat, slots: [hear, fact, next], blocks[] }
```
Правила: блоки склеиваются в связную фразу без правки текста; для каждого блока заданы `compatibleWith` (чтобы сборка не давала бессвязный ответ); количество верных сборок больше одной (разные «факты» из `ideas`), поэтому оценка идёт по блокам, а не по совпадению с одним эталоном.

**Что нужно решить до реализации.**
1. Стиль склейки: связки («поэтому», «кстати») хранить в блоках или добавлять приложением.
2. Сколько верных сочетаний допустимо на возражение (минимум два, чтобы не было «одного эталона»).
3. Как оценивать полноту: «обязательные идеи» (`critical`) как набор блоков, а не как поиск слов.
4. Дополнить `discovery`: блок «уточнить» с вопросом клиенту (сейчас критерий почти не оценивается).
5. Перенос веб-фактов в блоки: только `claim`, с атрибуцией, с проверкой `validate.py`.
