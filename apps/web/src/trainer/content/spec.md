# Тренажёр продаж для партнёров MultiFrame — техническое задание

Версия 1 · статус: к реализации · язык интерфейса: русский, без англицизмов.
Все данные лежат рядом с этим файлом: `objections.json`, `scenarios.json`, `quiz.json`, `scoring.json`. Проверка содержимого: `python3 tools/validate.py` (эталонная автооценка — `tools/score_reference.py`).

---

## 1. Цель и границы

Дать каждому кабинету партнёра короткую, честную и измеримую тренировку: уметь ответить на возражение клиента фактами из обучающих видео, не обещать лишнего и договориться о следующем шаге.

Тренажёр живёт внутри существующего раздела «Обучение», работает без сети, ничего не создаёт в рабочих данных (сделки, клиенты, расчёты, продажи).

**Что входит:** три режима (быстрая отработка, ролевой сценарий, проверка знаний), оценка без нейросети, прогресс, интервальное повторение, банк возражений для панели «Что ответить клиенту».

**Что не входит (этап 2, отдельные задачи):** оценка нейросетью; командная статистика владельца на сервере; голосовой ввод; генерация новых сценариев.

### 1.1. Жёсткие правила содержания (нарушение = ошибка приёмки)

1. Единственный источник фактов — расшифровки семи обучающих видео. Каждый эталонный ответ и каждый вопрос викторины подтверждён короткой дословной цитатой (`sourceQuotes`). Проверка дословности входит в `tools/validate.py`.
2. Нельзя использовать: «до 17 дБ», «гипоаллергенный», «SmartLock» (замок называется SHIPPASS), цены и суммы, проценты «дешевле на N %», заработок партнёра, срок службы и гарантийный срок. Эти слова допустимы только в списках запрещённого (`forbiddenClaims`, `scoring.globalForbidden`, поле `commonMistake`, неверные варианты викторины).
3. Тишину не обещаем. Формулировка из видео: «ни одна система не делает квартиру абсолютно беззвучной; задача — повысить акустический комфорт и сделать шум менее раздражающим и заметным».
4. Результаты испытаний называем честно и с условиями: потолок, исходный уровень 57 дБ — **+1 дБ**; стена, исходный уровень 38 дБ — **+9 дБ**. Нельзя приписывать потолку результат стены. Цифру для квартиры клиента не называем. В массовом жилье исходный уровень 38–45 дБ; замера потолка при таких значениях в видео нет — это сказано в ответах прямо.
5. Об огне — только «не поддерживает горения, не выделяет опасного чёрного дыма, не подвержен горячему каплепадению». Слов «негорючий», «не горит» нет.
6. О пыли — «нет сильного пыления», а не «пыли нет совсем». Об аллергии — только «отсутствие пыли и вредных частиц особенно важно для семей с детьми и аллергиков»; нельзя «безопасно аллергикам».
7. Тексты для пользователя — на русском. Исключения: названия продукта и замка (MultiFrame, Wave, Flat, SHIPPASS), «дБ». Ключи JSON и идентификаторы — латиницей.

## 2. Состав данных

| Файл | Содержимое | Объём |
|---|---|---|
| `objections.json` | банк возражений, 12 причин отказа | 36 возражений |
| `scenarios.json` | ролевые сценарии | 12 сценариев, 34 шага |
| `quiz.json` | вопросы по продукту, 9 тем | 51 вопрос |
| `scoring.json` | критерии 1–5, якоря, шаблоны автооценки, запрещённые утверждения, пороги, интервалы повторения | 6 критериев |

Каждый файл содержит `schemaVersion` (сейчас 1) и реестр `videos` (код `В1`…`В7`, идентификатор материала, название). Цитаты ссылаются на видео по `videoCode`.

Версия контента (`contentVersion`) = хэш четырёх файлов; сохраняется в каждой попытке.

### 2.1. Возражение (`objections.json → objections[]`)

```
id                     строка, например "obj-price-expensive"
type                   price | competitor | trust | expectation | technical | safety | installation | timing | need | space | decision_maker
refusalReasonKey       ключ из refusalReasons (см. 2.5)
roles                  [owner | manager | measurer | crew | stp_admin]
difficulty             1–3
clientPhrasing[]       2–3 способа, как клиент говорит это; в тренажёре выбирается один
pushback               вторая реплика клиента («дожим»); тренируемый отвечает ещё раз
referenceAnswer        эталон на первую реплику
pushbackReferenceAnswer эталон на повтор
requiredPoints[]       { id, beat: 1|2, text, anyOf[], minMatches?, critical, quoteIds[] }
forbiddenClaims[]      { id, text, patternsRef? }  id вида "g-…" — глобальное правило из scoring.json; "l-…" — местное
sourceQuotes[]         { id: "q1", videoCode, quote, appliesTo: answer|pushback|both }
commonMistake          типичная ошибка, одной фразой
panel                  { title, shortAnswer, keyFact, showMaterial[{videoCode,title,hint}], priority 1–4 } для панели «Что ответить клиенту»
```

Правила:
- `anyOf` — список регулярных выражений. Пункт засчитан, если совпали не менее `minMatches` (по умолчанию 1) разных выражений. Критичный пункт весит 2, обычный 1.
- Выражения записаны в нижнем регистре, без «ё». Без `\b`, `\w`, `\W` (в JavaScript они не работают с кириллицей) и без встроенных флагов. Перед проверкой текст нормализуется (раздел 5.1).
- `forbiddenClaims[].id` с префиксом `g-` ссылается на `scoring.globalForbidden`; с префиксом `l-` — местное правило без шаблонов (только для самооценки), если нет записи в `scoring.localForbiddenPatterns`.
- Одна цитата может подтверждать несколько пунктов; каждый пункт ссылается на цитаты через `quoteIds`.

### 2.2. Сценарий (`scenarios.json → scenarios[]`)

```
id, title, roles[], callType, difficulty 1–3, estimatedMinutes
persona          { name, age, description, mood, hiddenNeed, knowsAbout }
goal             цель тренируемого (одна фраза)
setup            вводная для экрана «Ситуация»
steps[]          { id, objectionId, clientPhrasingIndex, beats: 2, coachHint, afterPass, afterFail }
closing          { clientLine, requiresNextStep: true, goodExamples[] }
successCriteria[]{ id, kind: objectionPoints | noForbiddenClaims | nextStep | manual, text }
tags[]
```

Шаг = возражение из банка. Реплика 1 — `objection.clientPhrasing[clientPhrasingIndex]`, реплика 2 — `objection.pushback`. После двух ответов показывается `afterPass` (если шаг засчитан) или `afterFail`. Реплики `afterPass`/`afterFail`, персона и вводная — авторский текст для обучения, а не утверждения о продукте; продуктовых фактов в них нет. После последнего шага — `closing.clientLine`; тренируемый должен предложить следующий шаг (действие, срок, кто делает).

### 2.3. Вопрос викторины (`quiz.json → questions[]`)

```
id, topic, difficulty 1–3, type: "single" | "multi"
question, options[{id, text}], correctOptionIds[], explanation
sourceQuotes[]   { id, videoCode, quote }
isTrap           true — вопрос про типичную ошибку (чужая цифра, «негорючий», «тишина» и т. п.)
roles[], relatedObjectionIds[]
```
Порядок вариантов уже перемешан, при показе перемешиваем заново (с зерном от id вопроса и номера попытки). Вопросы-ловушки при ошибке показывают связанное возражение (`relatedObjectionIds`) как ссылку «Потренировать».

### 2.4. Оценка (`scoring.json`)

Описана в разделе 5. Ключевые поля: `criteria[]`, `modes`, `coverageToScore`, `capIfCriticalMissing`, `honestyGate`, `passThresholds`, `negationWords`, `globalForbidden[]`, `ackStarters`, `openQuestionStarters`, `valueLinkPattern`, `nextStep{action,time,who}`, `srs`.

| cheaper_alternative | «Нашли дешевле / другой материал» | |
| other_solution | «Выбрали другое решение (каркас, многослойное)» | |
| doubt_effect | «Сомневается в эффекте / нужна гарантия» | да |
| unrealistic_expectation | «Ждёт полной тишины» | |
| doubt_safety | «Опасения за здоровье и экологию» | да |
| install_too_long | «Долго и неудобно монтировать» | да |
| postpone_decision | «Подумает потом / отложил» | да |
| not_needed | «Шум не мешает / не нужно» | |
| lose_space | «Жалко высоту и площадь» | |
| decision_maker | «Решает не он один» | |
| need_details | «Нужны уточнения по продукту или монтажу» | |

Если в проекте уже есть собственный справочник причин отказа, нужно сопоставить значения один раз в коде; ключи в JSON не переименовывать, добавлять новые можно.

## 3. Режимы

### 3.1. Быстрая отработка («Отработать возражение»)

Для коротких подходов по 2–3 минуты.

1. Пользователь открывает «Обучение → Тренажёр продаж → Быстрая отработка». Колода собирается из возражений, подходящих его роли (`objection.roles ∋ role`); порядок — сначала просроченные по расписанию повторений, потом новые, потом остальные; в подходе 5 возражений (изменяется в «Настройках подхода», маленькая форма в модальном окне по центру).
2. **Реплика 1.** Показываем реплику клиента (одну из `clientPhrasing`, чередуем) и поле ввода (многострочное, минимум 8 слов; кнопка «Ответить»; «Не знаю» разрешено — тогда 1 балл и сразу показывается эталон).
3. **Реплика 2.** Показываем `pushback`, снова поле ввода.
4. **Разбор.** Экран-страница с блоками: «Ваш ответ» с подсветкой найденных пунктов; список пунктов (✔ названо / ✖ не названо, критичные отмечены); найденные нарушения с объяснением; эталон реплик 1 и 2; цитаты из видео (название ролика, дословный текст) с кнопкой «Открыть видео» (если материал доступен); типичная ошибка.
5. **Самооценка.** Шесть критериев (в этом режиме пять: «Следующий шаг» не применяется; «Выяснение потребности» — по желанию) — по 1–5, с якорями; предварительно проставлена автооценка, пользователь может изменить на 1 балл вверх или вниз без объяснений и больше — с короткой пометкой. В итог идёт оценка пользователя, автооценка сохраняется отдельно.
6. Кнопки: «Следующее возражение», «Повторить это», «Закончить». После последней карточки — итог подхода: средний балл, сколько засчитано, что повторить.

### 3.2. Ролевой сценарий («Разговор с клиентом»)

Длительность 6–8 минут. Экран «Ситуация» (персона, цель, подсказка) → шаги → заключительная реплика → итог.

1. Экран «Ситуация»: имя и описание клиента, цель, роль пользователя, что нужно получить («конкретный следующий шаг»). Кнопка «Начать разговор».
2. Для каждого шага: клиентская реплика → ответ пользователя → повтор (`pushback`) → ответ пользователя → реплика `afterPass`/`afterFail` (шаг засчитан, если по этому шагу охват ≥ 0,6 и нет критичных нарушений). Подсказка `coachHint` доступна по кнопке «Подсказка»; использованная подсказка снижает оценку шага не более чем на 1 балл по критерию «Ответ на возражение».
3. Заключительная реплика (`closing.clientLine`): пользователь предлагает следующий шаг. Оценивается критерий «Следующий шаг» (5.4).
4. Итог: оценка шести критериев по всему разговору, критерии сценария (`successCriteria` — отмечаются автоматически, кроме `manual`, их пользователь отмечает сам), разбор по шагам со ссылками на эталоны и цитаты, пример хорошего следующего шага (`goodExamples`).
5. Сценарий можно прервать, прогресс шага сохраняется как черновик на устройстве (до 7 дней).

### 3.3. Проверка знаний («Викторина»)

1. Выбор: «Быстрая (10 вопросов)», «По теме», «Ловушки» (только `isTrap`), «Повторить» (по расписанию). Вопросы подбираются по роли пользователя.
2. Один вопрос на экране; после ответа сразу показываем верный вариант, пояснение и цитату из видео; затем «Дальше».
3. Итог: процент верных, разбивка по темам, список ошибок со ссылками на связанные возражения (`relatedObjectionIds`) и кнопкой «Потренировать».
4. Критерий «Честность» в викторине = доля верных ответов на вопросы-ловушки (≥ 80 % = 5, 60–79 % = 4, 40–59 % = 3, 20–39 % = 2, меньше = 1; если ловушек в подходе нет — критерий не считается).

## 4. Экраны и потоки по ролям

Размещение: раздел «Обучение» (внутри него отдельная карточка «Тренажёр продаж»). Настольная версия — левое меню; телефон — меню-«бургер». Все содержательные экраны открываются страницами; маленькие формы (настройки подхода, фильтр, подтверждение сброса прогресса, пометка к самооценке) — окном по центру.

**Маршруты (страницы):**
- `Обучение → Тренажёр продаж` — главная: «Сегодня» (что повторить, подход на 5 минут), три плитки режимов, «Мой прогресс».
- `…/отработка` и `…/отработка/:id` — быстрая отработка и разбор карточки.
- `…/сценарии`, `…/сценарии/:id` (ситуация), `…/сценарии/:id/разговор`, `…/сценарии/:id/итог`.
- `…/викторина`, `…/викторина/итог`.
- `…/прогресс` — прогресс по критериям, темам, причинам отказа, история попыток.
- `…/банк-возражений` — справочник: список возражений с фильтром по причине отказа; карточка показывает `panel`, эталоны и цитаты.

| Роль | Основной путь | Что видит |
|---|---|---|
| Владелец партнёра | «Сегодня» → быстрая отработка (цена, конкуренты, доверие, решение) → сценарии «Владелец убеждает мастера», «Скептик-инженер», «Клиент говорит “дорого”» | всё содержимое для `owner`; «Мой прогресс». Командная статистика — этап 2 |
| Менеджер | «Сегодня» → быстрая отработка → сценарии звонков («Первый звонок», «После коммерческого предложения», «Повторный звонок», «Спутник решения») → викторина «Как продавать» | возражения и сценарии для `manager`; банк возражений с фильтром по причине отказа |
| Замерщик | быстрая отработка по теме «Высота и площадь», «Провода», «Честность по потолку» → сценарий «Замерщик на объекте» → викторина «Монтаж» и «Высота и площадь» | возражения и вопросы для `measurer` |
| Монтажник (бригада) | быстрая отработка («На чём держится», «Как резать», «Качество монтажа», «Безопасность») → сценарий «Монтажник на объекте» → викторина «Монтаж» | возражения и вопросы для `crew` |
| Администратор СТП | как менеджер + просмотр всего содержимого, версии контента и результатов проверки; кнопка «Скопировать цитату» | всё |

Правила доступа: роль берётся из учётной записи; пользователь может переключить фильтр «Показать все роли» (маленькая форма), но прогресс считается по его роли. Если у роли нет сценариев (в текущем наборе есть у всех пяти), показывается сообщение с предложением быстрой отработки.

**Состояния экранов (для каждого):** загрузка, пусто, ошибка чтения содержимого («Не удалось загрузить тренажёр. Содержимое сохранено на устройстве — попробуйте обновить страницу»), нет сети (тренажёр работает; значок «Без сети» только у отправки результатов), успех.

## 5. Оценка без нейросети

### 5.1. Нормализация

Перед любой проверкой: нижний регистр, «ё» → «е», кавычки «»"“” → пробел, повторные пробелы → один. Все шаблоны в JSON уже написаны с учётом этого. Предложения делятся по `. ! ? ;` и переводу строки.

### 5.2. Критерии

Шесть критериев по шкале 1–5; якоря для самооценки — в `scoring.criteria[].anchors`. Критерий «доля речи» для текстового тренажёра неприменим, вместо него «Выяснение потребности» и «Слышу клиента».

| id | Название | Вес | Режимы | Автооценка |
|---|---|---|---|---|
| discovery | Выяснение потребности | 0,15 | отработка, сценарий | вопросы в ответе |
| listening | Слышу клиента | 0,15 | отработка, сценарий | признание + повтор слов клиента |
| objection | Ответ на возражение | 0,25 | отработка, сценарий | охват обязательных пунктов |
| value | Ценность для клиента | 0,15 | отработка, сценарий | факт + связка «для вас» |
| honesty | Честность утверждений | 0,20 | все | запрещённые утверждения |
| nextstep | Следующий шаг | 0,10 | сценарий | действие + срок + кто |

Итог = Σ(вес × оценка) / Σ(веса критериев, применимых в режиме). То есть при неприменимости критерия остальные веса пересчитываются в сумму 1. В быстрой отработке, если вопроса нет (`discovery = 1`), критерий исключается из итога (`discoveryOptionalInDrill`).

### 5.3. Автооценка по критериям (эталон: `tools/score_reference.py`)

Для каждой из двух реплик считается отдельно; затем объединяется (`score_step`).

1. **Ответ на возражение.** Для каждого пункта с реплики: засчитан, если совпали ≥ `minMatches` выражений из `anyOf`. Охват = Σ(вес засчитанных) / Σ(веса всех), критичный = 2. Оценка по таблице `coverageToScore`: [0 → 1], [0,2 → 2], [0,4 → 3], [0,6 → 4], [0,8 → 5]. Если пропущен критичный пункт — не выше `capIfCriticalMissing` (3).
2. **Честность.** Для всех предложений ответа ищем совпадения глобальных и местных запрещённых шаблонов. Совпадение **не считается**, если: (а) в пределах 6 слов перед ним стоит слово из `negationWords` («не обещаем тишину», «не могу гарантировать»), а у правила `negationAware = true`; (б) всё предложение совпало с одним из `exceptIfSentenceMatches` (например, «не поддерживает горения»). Одно критическое нарушение — оценка 1. Каждое предупреждение (`warn`, например скользкие формулировки или цена) — минус 1 от 5, не ниже 3.
3. **Выяснение потребности.** Нет вопросительного знака — 1; есть вопрос, но без открытого вопросительного слова — 3; есть открытый вопрос — 5.
4. **Слышу клиента.** 1 + 2, если ответ в первых 120 знаках начинается с признания (`ackStarters`) + 2, если повторены слова клиента (совпадают первые 5 букв хотя бы одного слова длиной ≥ 5 из реплики клиента).
5. **Ценность.** Нет засчитанных пунктов с цитатой — 1; есть факты, но нет обращения к клиенту (`valueLinkPattern`) — 3; факты + обращение — 4; два и более факта + обращение — 5. Достоверность автооценки низкая; на разборе обязательно предлагаем самооценку.
6. **Следующий шаг** (только сценарий, заключительная реплика). Нет действия (`nextStep.action`) — 1; есть действие — 3; действие и срок (`nextStep.time`) — 4; действие, срок и исполнитель (`nextStep.who`) — 5. Все `goodExamples` проходят проверку на 5 (проверяется в `validate.py`).

### 5.4. Ограничение по честности (`honestyGate`)

Если «Честность» ≤ 2, итог не выше 2,4: попытка не засчитывается, как бы хорошо ни были названы остальные пункты. Пользователь видит причину («Обещание тишины», «Результат стены приписан потолку» и т. п.), цитату из видео и правильную формулировку.

### 5.5. Порог «засчитано» (предварительные значения, уточнить по пилоту)

- Быстрая отработка: итог ≥ 3,5, «Честность» ≥ 4, «Ответ на возражение» ≥ 3.
- Сценарий: итог ≥ 3,5, «Честность» ≥ 4, «Следующий шаг» ≥ 3.
- Викторина: ≥ 80 % верных ответов.
- Уровни: «Начинающий» (< 3,5), «Уверенный» (≥ 3,5), «Мастер» (≥ 4,3) — по среднему итогу последних 10 попыток.

### 5.6. Самооценка

- Показываем автооценку и якоря; пользователь может скорректировать каждый критерий. Изменения более чем на 1 балл просят короткую пометку («почему»).
- Чек-вопросы критерия (`selfChecklist`) показываются свёрнутым блоком «Проверить себя».
- Можно проходить полностью по самооценке, если автооценка отключена в настройках (например, ответ дан устно). В этом случае вводится только оценка по якорям, эталон показывается сразу.

### 5.7. Защита от «подбора слов»

- Минимум 8 слов в ответе; ответ из одних перечисленных ключевых слов без связных предложений не засчитывается (проверка: не менее 2 предложений или 15 слов для критичных пунктов — настраивается).
- Эталон всегда показывается после ответа, самооценка обязательна; в расчёт идёт итоговая оценка пользователя.
- Автооценка — подсказка, не экзамен. В интерфейсе пишем «Предварительная оценка».

### 5.8. Необязательный этап: нейросеть (позже)

Если включён и есть сеть, ответ, эталон, `requiredPoints` и якоря отправляются на оценку; результат хранится как `llmScores` рядом с `autoScores`, в итог не подмешивается без подтверждения пользователя. Нейросеть не должна добавлять факты вне `sourceQuotes`. Без сети или при ошибке работает только автооценка.

## 6. Прогресс и интервальное повторение

- Единица повторения — возражение или вопрос (`objections.id`, `quiz.id`). Сценарии не повторяются по расписанию, но их шаги обновляют карточки возражений.
- Коробки 1–5 с интервалами 0 / 1 / 3 / 7 / 21 дней (`scoring.srs`). «Засчитано» — коробка + 1 (не выше 5); «не засчитано» — коробка = 1. `nextDueAt = lastAt + интервал[коробка]`.
- Очередь «Сегодня»: карточки с `nextDueAt ≤ сейчас`, сверху низкая коробка и большая просрочка; лимит `srs.dailyLimit` (10) в день; новые карточки добавляются, если очередь короче лимита.
- «Мой прогресс»: средний балл по каждому из шести критериев (последние 10 попыток); освоено / в работе / не начато по темам и по причинам отказа (карточка «освоена» в коробке ≥ 4); серия дней (без наказания за пропуск); список слабых мест (критерии < 3,5, часто пропускаемые пункты `missedPointIds`).
- Сброс прогресса — в маленьком окне подтверждения; удаляет данные только на этом устройстве.

## 7. Повторное использование банка возражений: панель «Что ответить клиенту»

Панель в карточке проекта менеджера читает тот же `objections.json`, ничего не копируя:

1. Менеджер выбирает причину отказа клиента (`refusalReasonKey`).
2. Панель показывает возражения с этой причиной по `panel.priority` (1 — самые частые). Для каждого: `panel.title`, `panel.shortAnswer`, `panel.keyFact`, ссылки на материалы (`panel.showMaterial`) и кнопка «Потренировать» (открывает карточку быстрой отработки).
3. Короткие ответы (`panel.shortAnswer`) только из подтверждённых фактов; запрещённые утверждения (`forbiddenClaims`) показываются в свёрнутом блоке «Чего не говорить».
4. Использование панели — это не попытка тренировки и не меняет коробки.
5. Кнопка «Скопировать ответ» копирует `panel.shortAnswer` в буфер; текст можно править перед отправкой клиенту (менеджер отвечает за итог).

## 8. Работа без сети и синхронизация

- Четыре файла JSON и реестр видео кладутся в предзагрузку сервисного работника с версией; обновление содержимого — по версии `contentVersion`, с показом «Доступны новые вопросы» (без прерывания текущего подхода).
- Все попытки пишутся сразу в IndexedDB; `synced = false`. При появлении сети — отправка очередью (идемпотентно по `attempt.id`). Если на сервере нет конечной точки, этап 1 работает полностью локально, а очередь накапливается и отправляется после появления конечной точки.
- Видео не обязательны в офлайне: если ролик недоступен, показываем цитату и название ролика.
- Попытка тренировки **никогда** не создаёт и не изменяет сделки, клиентов, проекты, расчёты, продажи или события учёта. Поле `context: "training"` обязательно.
- Данные на устройстве привязаны к `userId`; при выходе из кабинета другого пользователя прогресс не виден.

## 9. Доступность и язык

- Весь текст интерфейса — по-русски, без англицизмов: «подход», «разбор», «возражение», «следующий шаг», «повторить», «ловушка», «без сети». Не использовать: «фидбек», «кейс», «дедлайн», «скрипт», «чек-лист», «онлайн/офлайн», «челлендж», «стрик».
- Контраст, размер шрифта ≥ 16 px на телефоне, поле ввода растягивается, клавиатура не закрывает кнопку «Ответить».
- Все действия доступны с клавиатуры; фокус виден; подсветка в разборе не опирается только на цвет (значки ✔ и ✖ и слова «названо / не названо»).
- Экраны работают на ширине 360 px и на настольных экранах; на настольном — две колонки: слева разговор, справа подсказки и цитаты.

## 10. Критерии приёмки

Содержимое:
1. `python3 tools/validate.py` завершается кодом 0: все JSON читаются, нет ошибок, нет предупреждений.
2. В `objections.json` 25–40 возражений (сейчас 36), у каждого ≥ 2 формулировок клиента, повтор, два эталона, пункты, запрещённые утверждения и цитаты; все цитаты дословно есть в расшифровках.
3. Основные пять причин отказа покрыты возражениями.
4. В `quiz.json` ≥ 30 вопросов (сейчас 51), у каждого цитата; ≥ 10 % вопросов-ловушек.
5. В `scenarios.json` 8–12 сценариев (сейчас 12), охвачены все пять ролей; в каждом есть критерий конкретного следующего шага.
6. Запрещённые слова и цифры (раздел 1.1) не встречаются в эталонах, ответах панели, вопросах, сценариях.

Режимы:
7. Быстрая отработка: цикл «реплика → ответ → повтор → ответ → разбор → самооценка» проходит без сети; в подходе по умолчанию 5 карточек.
8. Пустой ответ или менее 8 слов не отправляется; «Не знаю» разрешено и даёт 1 балл с показом эталона.
9. Разбор показывает найденные и не найденные пункты, нарушения, оба эталона, цитаты из видео и типичную ошибку.
10. Ролевой сценарий: экран «Ситуация», все шаги по 2 реплики, заключительная реплика, итог по шести критериям.
11. Подсказка доступна, её использование отмечено в попытке (`usedHint`).
12. Викторина: 10 вопросов за подход, сразу показываются верный ответ, пояснение и цитата; итог по темам; ошибки в ловушках ведут к возражению.

Оценка:
13. Автооценка совпадает с `tools/score_reference.py` на тестовых примерах; эталонные ответы всех 36 возражений получают 5 по охвату и честности.
14. «Мы не обещаем тишину: ни одна система не делает квартиру абсолютно беззвучной» не считается нарушением; «Гарантирую полную тишину» — критическое нарушение. То же для фраз из `tools/validate.py` (отрицательные и положительные тесты).
15. Критическое нарушение по честности ограничивает итог до 2,4 и объясняется пользователю с цитатой.
16. Итог пересчитывает веса критериев, неприменимых в режиме; в быстрой отработке «Следующий шаг» не участвует.
17. Пользователь может изменить автооценку; в попытке сохраняются обе оценки.

Прогресс:
18. Коробки и сроки повторения соответствуют `scoring.srs`; очередь «Сегодня» не превышает 10 карточек.
19. «Мой прогресс» показывает средние по критериям, темам и причинам отказа, историю попыток, слабые места.
20. Сброс прогресса удаляет только данные на этом устройстве после подтверждения.

Работа без сети и безопасность:
21. После первой загрузки тренажёр открывается и работает в режиме «без сети»; попытки сохраняются и отправляются очередью после появления сети.
22. Попытка не создаёт и не меняет сделки, клиентов, расчёты, продажи (проверка тестом по сетевым вызовам и хранилищу).
23. Панель «Что ответить клиенту» открывается по `refusalReasonKey`, использует тот же файл, показывает `panel.*` и не меняет прогресс.

Интерфейс:
24. Меню слева (настольная версия) и «бургер» (телефон); экраны разбора, сценария, итога — страницы; маленькие формы — окна по центру.
25. Нет англицизмов в тексте интерфейса; все надписи по-русски.
26. На ширине 360 px кнопка «Ответить» не перекрывается клавиатурой; контраст не ниже AA.

## 11. Известные пробелы и неоднозначности (решить до запуска или принять)

1. **Цены и деньги.** В видео есть цены, проценты экономии и заработок партнёра, но они не сверены и частично противоречат друг другу (например, «на 40 % ниже» в таблице, «на 20–30 % дороже» в тексте, разные цифры за м² в разных местах). По указанию они исключены. Возражения о цене отвечают без цифр и предлагают свой расчёт партнёра. Если нужны цифры, нужен подтверждённый прайс отдельным файлом.
2. **Испытание измеряло воздушный шум.** Для шагов (ударный шум) цифр нет; в ответах про шаги говорится только, что система помогает снизить такой шум и что тишину не обещаем.
3. **Потолок при исходном уровне 38–45 дБ** не измерялся. В ответах: «у нас замера нет; специалисты по акустике прогнозируют несколько дБ как очень хороший результат» — это цитата из видео об ожиданиях, а не измерение.
4. **Срок службы, гарантия, ресурс** в видео не названы; в ответах прямо сказано «не называем».
5. **Противоречие в видео про стену (В6):** «плотное примыкание ко всем поверхностям» и «избегайте плотного соприкосновения каркаса с поверхностью». Возможна ошибка распознавания; в содержимое не включено.
6. **Видео В7** — десять секунд без речи (автоматическая расшифровка «Слышен звук» ненадёжна). Файла звука в расшифровках нет: для аудио-демо нужен исходный ролик; тренажёр лишь ссылается на него (`showMaterial`).
7. **Нет отдельных видео** для замерщика (порядок замера), для бригады (приёмка, акт), для администратора СТП. Сценарии этих ролей составлены только из фактов монтажа и продаж; уточнения от СТП улучшат их.
8. **Нет видео про «Решает не он один» и про «Тихие соседи».** Ответы построены из общих положений видео (консультация без давления, материалы для передачи, двусторонний эффект, акустический комфорт) (для «Решает не один» это сказано в `panel.keyFact`).
9. **Таблица отработки возражений** из видео «Как продавать» (по QR-коду) в расшифровках отсутствует; если её дать, банк можно сверить.
10. **Авторский текст.** Реплики клиента, `pushback`, персоны, `afterPass/afterFail` и пояснения написаны для тренажёра; они не содержат утверждений о продукте сверх цитат. Эталоны ответов и пункты опираются только на цитаты.
11. **Пороги и веса предварительные.** Нужен пилот на 10–15 пользователях, чтобы откалибровать шаблоны (`anyOf`), пороги и веса; шаблоны подобраны под типичные формулировки и могут пропускать корректные ответы другими словами — поэтому самооценка обязательна.
12. **Названия:** «MultiFrame», «Wave», «Flat», «SHIPPASS» — как в видео (в расшифровке встречается и «SHIP PASS»); в интерфейсе писать «SHIPPASS».
13. **Размер:** `objections.json` около 280 КБ (около 70 КБ в сжатом виде); при необходимости можно загружать пункты и цитаты отдельно от формулировок.

## 12. Сопровождение содержимого

- Любое новое утверждение добавляется только вместе с цитатой из видео; запрос на изменение проходит `tools/validate.py`.
- При обновлении видео перепроверить цитаты (скрипт сообщит о ненайденных) и поднять `schemaVersion` при изменении структуры.
- Шаблоны `anyOf` пополнять по журналу пропущенных пунктов из пилота (поле `missedPointIds` с `selfScores`, где пользователь поставил высокую оценку, а автооценка низкую).
