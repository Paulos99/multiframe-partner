# Работа на объекте без интернета: технический план

Статус: план, код по нему пока не пишем. Он опирается на код ветки `cursor/room-project-redesign` (поверх `cursor/rebuild-docs`) от 9 ноября 2026.

## 1. Что должно работать без сети

Замерщик и монтажник на объекте, в подвале или в новостройке без связи.

| Действие | Замерщик | Монтажник | Сейчас без сети |
| --- | --- | --- | --- |
| Открыть приложение и список «Мои комнаты» на сегодня | да | да | приложение открывается из кэша, список берётся из IndexedDB (`objects`, `projects`). Но если в кэше нет страницы, приложение не откроется |
| Открыть карточку комнаты: адрес, телефон клиента, площадь, панели, документы | да | да | карточка открывается, PDF-файлы нет: их байты не лежат на устройстве |
| Указать или исправить площадь и ответы Проблемомера | да | нет | сохраняется в очередь `outbox` и уходит позже (`saveObjectSynced`) |
| Пройти Проблемомер и сохранить профиль | да | нет | ответы сохраняются, а PDF профиля ставится в очередь `mf_partner_doc_queue_v1` в `localStorage` (до 20 файлов) |
| Начертить потолок в калькуляторе | да | нет | **не работает**: калькулятор `/calculator/` не в предкэше, service worker его не обслуживает |
| Сделать фото «до», «в работе», «после» | «до» | все этапы | **не работает**: `apiUploadRoomPhoto` шлёт файл сразу, без очереди |
| Заметка к комнате | да | да | **нет такого поля** |
| Отметка этапа «замер сделан», «монтаж закончен» | да | да | **нет**: этап меняют только владелец и менеджер (`canMoveObjects`) |
| Видеть, что не отправлено | да | да | точка `SyncStatus` в шапке: «Офлайн · Не выгружено N». Фото и документы в этот счёт не входят |

## 2. Что уже есть в коде

- **PWA**: `vite-plugin-pwa` в `apps/web/vite.config.ts`. Предкэш хранит скрипты, стили и картинки. Страницы идут «сеть первой» за 4 секунды, офлайн открывается последняя копия (`mf-pages-v1`). API на другом домене, service worker его не трогает.
- **IndexedDB** `mf-partner-offline`, версия 2 (`src/partner/offlineDb.ts`). Хранилища: `objects`, `projects`, `outbox`, `projectOutbox`, `calculations`, `analytics`, `meta`.
- **Очередь и выгрузка**: `src/partner/syncEngine.ts` (`saveObjectSynced`, `flushOutbox`, `flushProjectOutbox`, `flushDocumentQueue`). Выгрузка запускается по событию `online` и при входе (`PartnerContext.tsx`). При 401 очередь не удаляется.
- **Конфликты на сервере**: `apps/api/index.js`, функция `incomingWins`. Побеждает запись с более поздним `updatedAt`. Проигравшая запись попадает в историю как `conflict_kept_server`. Часы клиента ограничены `clampClientTime`, запись из будущего больше чем на 5 минут не принимается.
- **Фоновая выгрузка** из service worker: `public/sw-sync.js`.
- **Сжатие фото**: `src/partner/photos/imagePrep.ts`. Длинная сторона до 1600 px, JPEG 0,8, без EXIF и GPS, превью 480 px. Сервер принимает до 1,8 МБ.
- **Офлайн-копии «Обучения»**: `offlineMaterials.ts`, докачка кусками по 8 МБ. Это готовый образец работы с Cache Storage.

## 3. Что сломано или мешает уже сейчас

1. **`sw-sync.js` открывает базу версии 1, а приложение уже на версии 2.** Браузер отвечает `VersionError`, и фоновая выгрузка из service worker молча не работает. Кроме того, в нём нет хранилища `projectOutbox`. Исправить первым: общая версия базы в одном месте и проверка на неё.
2. Очередь PDF лежит в `localStorage`: объём около 5 МБ на сайт, не больше 20 файлов, при переполнении файлы теряются молча. Её нужно перенести в IndexedDB.
3. У фото нет клиентского идентификатора. Повторная отправка после обрыва создаст дубль.
4. Калькулятор не открывается без сети, а для замерщика это главный инструмент.

## 4. Как устроить

### 4.1. Кэш приложения (service worker)

- Добавить в предкэш калькулятор (`public/calculator/**`): HTML, скрипты, шрифты. Для его страниц включить «сеть первой» с отдельным ключом, как у кабинета.
- Список «сегодня»: при каждом входе с сетью класть в IndexedDB все назначенные комнаты пользователя вместе с проектами. Это уже делают `replaceServerObjects` и `replaceServerProjects`. Добавить отметку «обновлено в 08:40», чтобы человек видел, насколько свежие данные.
- PDF документов назначенных комнат (профиль и смета) скачивать в Cache Storage `mf-room-docs-v1` по образцу `offlineMaterials.ts`. Ограничение — 50 МБ, самые старые файлы удаляются первыми.

### 4.2. Единая очередь в IndexedDB

Новая версия базы (3) и одно хранилище `queue` вместо разрозненных очередей:

```ts
type QueueItem = {
  id: string;            // клиентский идентификатор, он же ключ повтора на сервере
  kind: 'room' | 'project' | 'document' | 'photo' | 'note' | 'stage';
  objectId: string;
  userId: string;
  orgId: string;
  createdAt: string;     // время на устройстве
  baseUpdatedAt: string; // версия записи, с которой человек начинал правку
  attempts: number;
  lastError?: string;
  payload: unknown;      // фото — Blob, не base64
};
```

- Фото и PDF хранить как `Blob`, а не base64: так на треть меньше места.
- Порядок выгрузки: комнаты и проекты, затем заметки и отметки этапов, затем документы и фото. Внутри каждого вида — по `createdAt`.
- Повтор с паузой 5 с, 30 с, 2 мин, 10 мин. После 5 неудач элемент остаётся в очереди с пометкой «ошибка», и его можно отправить вручную.
- Перед записью проверять `navigator.storage.estimate()`. Если места меньше 50 МБ, предупреждать и не брать новые фото в очередь.
- Вызывать `navigator.storage.persist()`, чтобы браузер не стёр очередь при нехватке места.

### 4.3. Выгрузка

- Пусковые события: `online`, возврат на вкладку (`visibilitychange`), каждые 60 секунд при наличии сети и фоновая выгрузка service worker (Android Chrome; на iPhone её нет, там выгрузка идёт только при открытом приложении).
- Одновременно работает одна выгрузка. Блокировка через `navigator.locks`, чтобы две вкладки не слали одно и то же.
- Фото отправлять по одному с ходом загрузки. При обрыве фото остаётся в очереди целиком.
- **Сервер**: принимать клиентский `id` у фото, заметки и отметки этапа (`POST /objects/:id/photos` с полем `clientId`). Повтор с тем же `clientId` возвращает уже сохранённое без дубля. Новые пути добавить в `GATEWAY_PATHS` и `API_ROUTES`.

### 4.4. Конфликты

- Поля комнаты (площадь, ответы, адрес): оставить нынешнее правило «позже записано — то и верно» (`incomingWins`), но сравнивать `baseUpdatedAt`. Если на сервере запись менялась после того, как человек начал правку, сервер не перетирает её молча, а возвращает 409 с серверной версией. Приложение показывает «Пока вы были без сети, комнату изменил Иван. Оставить ваше или его?» с двумя кнопками.
- Фото и заметки только добавляются, поэтому не конфликтуют.
- Отметка этапа — это просьба, а не смена этапа. Она уходит менеджеру («Замер сделан 9 ноября в 14:20»), и этап он подтверждает сам. Права ролей не меняются. Если Павел решит, что замерщик сам ставит «Замер», это отдельное изменение прав, его надо согласовать.
- Удалённая на сервере комната: правки к ней не применяются, человек видит «Комнату удалили, ваши фото сохранены на телефоне», а фото можно скачать.

### 4.5. Сжатие фото

- Сжимать сразу после съёмки, до постановки в очередь, через `imagePrep.ts`: 1600 px, JPEG 0,8, ориентировочно 250–600 КБ на снимок. EXIF и GPS вырезаются.
- Тяжёлую работу перенести в `OffscreenCanvas` в отдельном потоке, чтобы интерфейс не замирал на старых телефонах. Если `OffscreenCanvas` нет, работать в основном потоке, как сейчас.
- Превью 480 px показывать в карточке сразу, ещё до отправки.

### 4.6. Как это выглядит для человека

- В шапке точка `SyncStatus` получает три состояния: «Нет связи» (серая), «Ждёт отправки: 3 фото, 1 замер» (жёлтая), «Всё отправлено» (зелёная). Нажатие раскрывает список с кнопкой «Отправить сейчас».
- Сверху карточки комнаты полоса «Нет связи — всё сохраняется на телефоне», пока нет сети.
- У каждого фото и документа в очереди значок: «на телефоне», «отправляется 40 %», «отправлено», «ошибка — повторить».
- Предупреждение при выходе из кабинета, если в очереди что-то есть: «3 фото ещё не отправлены. Если выйти, они останутся на телефоне и уйдут после входа».
- Всё по-русски, без слов «офлайн» и «синхронизация» в интерфейсе. Нынешние подписи «Офлайн · Не выгружено N» тоже заменить.

### 4.7. Заметки к комнате

Новое поле `notes: { id, text, by, at }[]` в комнате. Новый путь `POST /objects/:id/notes`, только добавление, правка своей заметки в течение 10 минут. Заметки видны всем, кому видна комната. Схема — в `packages/shared/schemas.js`.

## 5. Риски

| Риск | Что делаем |
| --- | --- |
| iPhone (Safari) удаляет данные сайта, если его не открывали 7 дней, и не умеет фоновую выгрузку | просить установить на экран «Домой», вызывать `storage.persist()`, напоминать «есть неотправленное» при открытии |
| Переполнение памяти телефона фотографиями | сжатие до очереди, проверка свободного места, предел очереди 300 фото |
| Двое правят одну комнату без сети | 409 и выбор человеком (4.4), история на сервере |
| Токен входа живёт 12 часов, а смена длинная | очередь не удаляется при 401 (уже так) и уходит сама после входа. Войти заново без сервера нельзя: так можно только в демо (`allowDeviceLogin`). Поэтому при истёкшем входе без сети показывать данные с телефона и продолжать копить очередь, а войти попросить, когда появится связь |
| Новая версия приложения меняет формат очереди | версия базы и перенос данных в `onupgradeneeded`, тест на перенос из версии 2 |
| Дубли фото при повторе | `clientId` на сервере (4.3) |
| Калькулятор в предкэше увеличит объём установки | измерить. Если больше 5 МБ, качать его отдельно кнопкой «Подготовить к работе без связи» |

## 6. Оценка по этапам

| Этап | Что входит | Срок |
| --- | --- | --- |
| 0 | Починить `sw-sync.js` (версия базы, `projectOutbox`), тест на это | 0,5 дня |
| 1 | Единая очередь в IndexedDB (версия 3), перенос старых очередей, `storage.persist`, проверка места | 2–3 дня |
| 2 | Фото без сети: сжатие до очереди, превью, отправка по одному, `clientId` на сервере, значки статуса | 3–4 дня |
| 3 | Калькулятор и PDF без сети: предкэш калькулятора, копии документов назначенных комнат | 2–3 дня |
| 4 | Заметки и отметки этапов как просьба менеджеру (API, схема, интерфейс) | 2–3 дня |
| 5 | Конфликты: `baseUpdatedAt`, 409, окно выбора | 2 дня |
| 6 | Индикаторы и тексты, предупреждение при выходе, проверка на телефонах (Android Chrome, iPhone Safari), e2e с отключённой сетью (`context.setOffline(true)`) | 2–3 дня |

Итого 14–19 рабочих дней. Этапы 0–2 дают главное: фото и замеры не теряются. Их можно выпустить отдельно, примерно за 6–8 дней.
