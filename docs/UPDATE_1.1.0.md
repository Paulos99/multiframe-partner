# Обновление кабинета до v1.1.0 (с v1.0.0)

Для разработчиков, которые ведут сервер https://stp-multiframe.ru. Код на сервере не правится: ставится готовая метка `v1.1.0`
(она лежит на ветке `main` репозитория https://github.com/Paulos99/multiframe-partner). Готовый архив статики
и контрольная сумма лежат в выпуске на GitHub, но на сервере с Docker он не нужен: образы собираются из метки.

## Что нового

- **Ссылка для входа (активация).** Администратор StP (для владельцев компаний и менеджеров StP) и владелец компании (для своих сотрудников)
  создают пользователя без пароля и выдают ему одноразовую ссылку `https://stp-multiframe.ru/cabinet/?activate=<токен>`. Она действует 24 часа, по ней человек сам придумывает пароль.
  Новая ссылка отменяет прежнюю. Та же кнопка «Ссылка для входа» работает как сброс пароля. Токен в хранилище не лежит: хранится только его хеш.
- **Минимальная длина пароля — 8 символов** (везде: вход, смена, активация, первый запуск).
- **Видео в «Обучении».** Первым пунктом, выше папок, у каждой роли своё видео: владелец, менеджер, замерщик, монтажник.
  Администратор StP видит все четыре, но только смотрит. У менеджера StP видео нет. Удалить видео из кабинета нельзя.
  Ролики лежат в образе `web` (`/cabinet/videos/…`), замена — только выпуском нового кода.
- **Плавная подсветка выбранного пункта** в меню, вкладках проекта и переключателе «Список / Канбан»; анимации в аналитике и канбане.
- **Нагрузка до 2000 пользователей.** Вход и журнал больше не переписывают основной файл; общий кэш, постраничные списки с ETag,
  тайм-аут 30 с с повторами, предел комнат без тихого вытеснения, аналитика по поясу.
- **Единые проверки запросов, схемы (zod), Node 22** в разработке и в образах.
- Исправлены три проверки аналитики, зависевшие от текущей даты.

## Что сделать до установки

1. **Резервная копия** хранилища (см. docs/handover/BACKUPS.md): объекты `platform-v2.json`, `analytics-events*.json`,
   `activity-log*.json`, `login-state.json` и бакет с фото и документами.
2. **Переменные окружения.** Новые необязательные (значения по умолчанию подходят):
   - `API_HEAP_MB` (1536) и `API_MEM_LIMIT` (`3g`) — память API; для 2000 пользователей поставьте 2048 и 3–4 ГБ;
   - `DOC_FRESH_MS`, `MAX_OBJECTS`, `ANALYTICS_EVENTS_CAP`, `AUDIT_LOG_CAP`, `LIST_CACHE_BYTES`, `ANALYTICS_TZ`, `COMPRESS`, `AUDIT_LOG_KEY`, `LOGIN_STATE_KEY` — описаны в docs/handover/ENV.md.
   Обязательных новых переменных нет, существующие значения остаются прежними.
   Пароль первого администратора (`ADMIN_BOOTSTRAP_PASSWORD`) теперь не короче 8 символов; на уже созданного администратора это не влияет.
3. **Миграции данных нет.** Формат документов читается с учётом старых версий. При первом обращении сами создаются новые объекты
   `activity-log.json` и `login-state.json` (журнал действий и счётчики неверных паролей раньше жили внутри `platform-v2.json`).
   Старые записи журнала остаются читаемыми.

## Установка

```bash
cd /opt/multiframe-cabinet            # каталог, куда клонировали репозиторий
git status --short                    # должно быть пусто: правок кода на сервере нет
./deploy/release.sh v1.1.0
```

Скрипт сам подтянет метку, проверит, что она на `main`, пересоберёт контейнеры `api` и `web`, дождётся ответов
`/cabinet/version.json` (должен вернуть `v1.1.0`) и `/cabinet-api/health` (`"ok":true`). Если проверка не прошла, он вернёт v1.0.0 сам.
Ручной откат: `./deploy/rollback.sh`.

## Внешний прокси: маршруты (обязательно проверить)

Сейчас на https://stp-multiframe.ru все запросы `/cabinet-api/*` отвечают 404: прокси не направляет их на API, из-за чего никто не может войти.
Нужны обе части на один и тот же локальный адрес контейнера `web` (`127.0.0.1:8081`, порт — `WEB_PORT`):

```nginx
location = /cabinet { return 301 /cabinet/; }
location /cabinet/ {
    proxy_pass http://127.0.0.1:8081;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;   # перезаписать, а не дополнить
    proxy_set_header X-Forwarded-Proto $scheme;
}
location /cabinet-api/ {
    proxy_pass http://127.0.0.1:8081;
    proxy_read_timeout 60s;
    client_max_body_size 10m;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Важно:
- Новые маршруты `POST /cabinet-api/auth/invite` и `POST /cabinet-api/auth/activate` лежат внутри `/cabinet-api/`, отдельной настройки не требуют.
  Если у вас прокси или шлюз пропускает только перечисленные пути, добавьте оба. Для шлюза Yandex Cloud они уже внесены в `GATEWAY_PATHS` (`infra/deploy_yc.py`).
- Рядом с ограничителем частоты на входе добавьте и `/cabinet-api/auth/activate` (docs/handover/DEPLOY.md, раздел «Ссылки активации»).
- Ссылка активации содержит токен в адресе страницы. Журналы доступа со строкой запроса не публикуйте: токен одноразовый и живёт 24 часа.
- Для видео прокси не должен ломать частичную загрузку (заголовок `Range`) и не должен кэшировать `/cabinet-api/`.
- Остальное по нагрузке — docs/handover/DEPLOY.md, раздел «Настройки под нагрузку».

## Проверка после установки

1. `curl -s https://stp-multiframe.ru/cabinet/version.json` → `"id":"v1.1.0"`.
2. `curl -s https://stp-multiframe.ru/cabinet-api/health` → `"ok":true` (до исправления прокси было 404).
3. Вход под администратором StP, открыть «Обучение»: видны четыре видео ролей, кнопок удаления нет, видео запускаются.
4. Под владельцем: «Обучение» — своё видео первым пунктом; в карточке сотрудника «Ссылка для входа» выдаёт ссылку, по ней в
   приватном окне задаётся пароль (минимум 8 символов), повторное открытие той же ссылки отвечает «Ссылка недействительна или срок истёк».
5. Пункты из docs/handover/SECURITY_CHECKLIST.md, затронутые выпуском.

## Если что-то пошло не так

`./deploy/rollback.sh` возвращает v1.0.0. Новые объекты `activity-log.json` и `login-state.json` при откате остаются в хранилище и не мешают.
Если пароль пользователя был задан по ссылке активации, он остаётся действующим и в старой версии.
