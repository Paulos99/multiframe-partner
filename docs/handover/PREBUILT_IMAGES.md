# Готовые образы: сервер ничего не собирает

С выпуска после v1.2.3 сервер не собирает интерфейс и API сам. Сборка `tsc` и `vite` требует больше памяти, чем есть на ВМ с 2 ГБ, и на выкладке v1.2.3 из-за этого зависла ВМ. Теперь образы собирает GitHub Actions, а сервер их только скачивает.

## Как это устроено

1. Владелец ставит метку `vX.Y.Z` на `main`.
2. Процесс «Образы для сервера (GHCR)» (`.github/workflows/images.yml`) собирает два образа и публикует их в GitHub Container Registry:
   - `ghcr.io/paulos99/multiframe-cabinet-api:vX.Y.Z`
   - `ghcr.io/paulos99/multiframe-cabinet-web:vX.Y.Z`

   Перед публикацией процесс проверяет, что `version.json` в образе отвечает этой меткой, а в образах нет файлов `.env`, ключей и переменных с секретами.
3. На сервере `./deploy/release.sh vX.Y.Z` скачивает эти образы (`docker compose pull`) и перезапускает контейнеры. Если образы ещё собираются, скрипт ждёт до 15 минут (`PULL_WAIT_SECONDS`).
4. Если новый выпуск не прошёл проверку, скрипт возвращает те образы, которые работали до установки. Ничего не скачивается и не собирается.

Сборка занимает около 5 минут после появления метки. Ставить метку и сразу запускать установку можно: скрипт подождёт.

## Что в образах

Секретов нет, поэтому пакеты можно сделать публичными:

- **api** содержит код `apps/api` и `packages/shared` и рабочие зависимости из `package-lock.json`. Тесты и служебные скрипты удаляются. Все ключи и пароли приходят при запуске из `deploy/.env`, внутри образа их нет.
- **web** содержит собранную статику и nginx. Параметры `VITE_*` попадают в код страницы и видны любому посетителю, поэтому секретами не являются.

Образы собираются из чистой копии репозитория. Файл `.dockerignore` дополнительно исключает `.env*`.

## Доступ к пакетам

Новый пакет в GHCR по умолчанию приватный. Подойдёт любой из двух вариантов.

**Публичные пакеты (рекомендуется).** Делается один раз после первой сборки, отдельно для `multiframe-cabinet-api` и `multiframe-cabinet-web`: GitHub → профиль → Packages → пакет → Package settings → Danger Zone → Change visibility → Public. Сделать пакет снова приватным потом нельзя. На сервере в этом случае ничего настраивать не нужно.

**Приватные пакеты.** Серверу нужен вход только на чтение:

1. GitHub → Settings → Developer settings → Personal access tokens (classic) → Generate new token. Выберите одно право `read:packages` и срок действия.
2. Впишите в `deploy/.env` на сервере (права файла 600):
   ```
   GHCR_USER=<логин GitHub>
   GHCR_TOKEN=<токен>
   ```
3. Скрипт входит в `ghcr.io` только на время скачивания и сразу выходит. Токен не сохраняется в настройках Docker и не передаётся в контейнер `api`.

Токен никому не присылайте и не коммитьте. Если он утёк, отзовите его в том же разделе GitHub.

## Переменные в `deploy/.env`

| Имя | Назначение |
|---|---|
| `IMAGE_PREFIX` | откуда брать образы, по умолчанию `ghcr.io/paulos99/multiframe-cabinet` (к нему добавляется `-api` и `-web`) |
| `GHCR_USER`, `GHCR_TOKEN` | вход на чтение для приватных пакетов (право `read:packages`). Для публичных пакетов не нужны |
| `PULL_WAIT_SECONDS` | сколько секунд ждать сборку образов на GitHub, по умолчанию 900. При откате 0 |
| `BUILD_ON_VM=1` | запасной вариант: собрать образы на сервере, как раньше. Нужно 3–4 ГБ памяти |

## Запасной вариант: сборка на сервере

```bash
BUILD_ON_VM=1 FORCE=1 ./deploy/release.sh vX.Y.Z
```

Нужен, если GitHub недоступен или образа для метки нет, например при откате на v1.2.3 и раньше: `BUILD_ON_VM=1 ./deploy/rollback.sh v1.2.3`. На ВМ с 2 ГБ памяти сборка может её повесить, поэтому перед ней лучше добавить swap.

## Параметры интерфейса

Готовый образ `web` собран со значениями по умолчанию (`/cabinet`, `/cabinet-api`, без демо). Номер Метрики и ссылки на инструменты StP задаются на GitHub: Settings → Secrets and variables → Actions → Variables, имена `CABINET_VITE_YM_ID`, `CABINET_VITE_ANALYTICS_INGEST_URL`, `CABINET_VITE_STP_PROBLEMOMER_URL`, `CABINET_VITE_STP_CALCULATOR_URL` (и при необходимости `CABINET_VITE_BASE`, `CABINET_VITE_API_URL`). После изменения пересоберите образы: Actions → «Образы для сервера (GHCR)» → Run workflow с текущей меткой, затем `FORCE=1 ./deploy/release.sh <метка>`.

Значения `VITE_*` из `deploy/.env` в режиме готовых образов не применяются, о чём скрипт предупреждает. Применить их можно только сборкой на сервере (`BUILD_ON_VM=1`).

## Переход с v1.2.3

На сервере сейчас работает скрипт установки из v1.2.3, а он собирает образы сам. Чтобы первая установка уже шла по-новому, переключитесь на метку до запуска скрипта:

```bash
cd /opt/multiframe-cabinet
git fetch --tags --force origin
git checkout --detach vX.Y.Z
FORCE=1 ./deploy/release.sh vX.Y.Z
```

Процесс «Deploy production» делает это сам. Дальше скрипт установки при обновлении вперёд сам переходит на свою версию из новой метки.

## Как проверить на следующем выпуске

1. После метки на GitHub зелёный процесс «Образы для сервера (GHCR)», в его сводке два адреса образов.
2. Пакеты видны в профиле на GitHub в разделе Packages. Если выбран вариант с публичными пакетами, переключите видимость (см. выше).
3. Скачивание без входа работает: `docker pull ghcr.io/paulos99/multiframe-cabinet-web:vX.Y.Z` (для приватных пакетов нужен вход с токеном).
4. На сервере в выводе `release.sh` есть «Скачиваем готовые образы» и нет шагов сборки (`npm ci`, `vite build`). Память во время установки почти не растёт (`free -m`).
5. `docker compose --env-file deploy/.env -f deploy/docker-compose.yml images` показывает `ghcr.io/paulos99/multiframe-cabinet-*` с этой меткой.
6. `/cabinet/version.json` отвечает меткой, `/cabinet-api/health` отвечает `"ok":true`.
