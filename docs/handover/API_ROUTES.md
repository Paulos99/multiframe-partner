# Маршруты API и шлюз

Источник списка — `GATEWAY_PATHS` в `infra/deploy_yc.py`. Права проверяет сам API в каждом запросе; шлюз и прокси их не заменяют.

## Как маршруты попадают наружу

- **Ваш сервер.** Контейнер `web` (nginx) отдаёт всё, что начинается с `/cabinet-api/`, в контейнер `api`, префикс срезается. Список путей
  вести не нужно: новые маршруты появляются вместе с выпуском.
- **Стенд владельца (Yandex Cloud).** Облачная функция стоит за API-шлюзом: каждый путь описан в спецификации отдельно, на любой метод.
  Новый маршрут в коде = новая строка в `GATEWAY_PATHS` и обновление шлюза скриптом `infra/deploy_yc.py`. Если маршрут не добавлен, шлюз отвечает 404.
- Если вы ставите свой API-шлюз перед `/cabinet-api/`, опубликуйте в нём **все** пути ниже и переустанавливайте список при каждом выпуске, где он менялся
  (владелец пишет об этом в описании метки).

В таблице пути без префикса `/cabinet-api`. `{…}` — параметр пути.

## Общие

| Путь | Назначение |
|---|---|
| `/`, `/health` | проверка работы |
| `/auth/login`, `/auth/me`, `/auth/logout` | вход, текущий пользователь, выход |
| `POST /auth/invite` | одноразовая ссылка активации для сохранённого пользователя: `{userId}` → `{path: '?activate=<токен>', expiresAt}`. Админ — для владельцев, менеджеров StP и других администраторов; владелец — для сотрудников своей компании. Это же сброс пароля. 20 вызовов за 15 минут на пользователя |
| `POST /auth/activate` | без входа: `{token, password}`. Токен ищется по хэшу и сроку, пароль сохраняется, все прежние входы закрываются. 10 попыток за 15 минут на адрес. Любая ошибка токена — один ответ «Ссылка недействительна или срок истёк» |
| `POST /auth/register` | без входа: владелец сам регистрирует компанию `{firstName, lastName, companyName, city, login, password, passwordRepeat, website}` (`website` — скрытое поле-ловушка, должно быть пустым). Создаёт компанию со статусом заявки «на проверке» и владельца, отвечает как вход `{token, user}`. Занятый логин — 409. 5 новых кабинетов в час на адрес (`REGISTER_IP_LIMIT`). Подробнее — [OWNER_REGISTRATION.md](OWNER_REGISTRATION.md) |
| `/me`, `/me/password`, `/me/avatar` | профиль, смена пароля, аватар |

## Компания партнёра

| Путь | Назначение | Роли |
|---|---|---|
| `/partner/profile` | карточка компании (правка) | admin, owner |
| `/org/settings` | настройки и цены (правка) | admin, owner |
| `/org/staff`, `/org/staff/{staffId}`, `/org/staff/reset-password` | сотрудники: список, создание, правка, удаление, новый пароль. Менеджер добавляет менеджеров, замерщиков и монтажников, как владелец | owner, sales |

## Администратор StP

| Путь | Назначение |
|---|---|
| `/admin/partners`, `/admin/partners/{partnerUserId}` | партнёры: список, создание, удаление |
| `POST /admin/partners/{partnerUserId}/approve`, `POST /admin/partners/{partnerUserId}/reject` | заявка самостоятельной регистрации: подтвердить или отклонить (`{reason}` необязательно). Отклонение закрывает вход всем пользователям компании (403, `code: registration_rejected`); подтверждение открывает снова |
| `/admin/partners/reset-password` | новый пароль владельца партнёра или менеджера StP |
| `/admin/stp-managers` | менеджеры StP: `GET` список, `POST` создание |
| `/admin/stp-managers/{managerId}` | `DELETE` удаление менеджера StP |
| `/admin/stp-admins` | администраторы StP: `GET` список, `POST` создание |
| `/admin/stp-admins/reset-password` | новый пароль администратора StP |
| `/admin/stp-admins/{adminId}` | `PATCH` отключить/включить или переименовать; `DELETE` удаление. Нельзя удалить/отключить себя и последнего активного администратора |
| `/admin/demo/reset` | сброс к демо-данным. Работает только при `ALLOW_DEMO_RESET=1` (стенд); на боевом не задавать |

Менеджеры StP живут во внутренней компании `org_stp`. Сами они вызывают только вход и профиль, чтение материалов и `/training/*`; всё остальное — 403.

Администраторов StP может быть несколько: первый — через `ADMIN_BOOTSTRAP_*` в пустом хранилище, следующих добавляют в кабинете (раздел «Кабинеты» → «Администраторы StP») или через `POST /admin/stp-admins`. После первого входа уберите `ADMIN_BOOTSTRAP_*` из окружения.

## Проекты, комнаты, документы, фото

| Путь | Назначение |
|---|---|
| `/projects`, `/projects/{projectId}` | проекты: список, создание, правка, архив |
| `/calendar`, `/calendar/{visitId}`, `/calendar/reminders` | календарь замеров и монтажей: выезды по ролям, создание и правка (владелец, менеджер), «выполнено» у своего выезда (замерщик, монтажник), отметки напоминаний «готово» и «отложить» |
| `/objects`, `/objects/{objectId}` | комнаты: список, создание, правка, статус, назначение, отказ |
| `/objects/{objectId}/documents`, `/objects/{objectId}/documents/{docId}` | PDF комнаты |
| `/objects/{objectId}/photos`, `/objects/{objectId}/photos/{photoId}` | фото и подписи; показ клиенту |
| `/objects/{objectId}/notes` | `POST` заметка к комнате: только добавление, повтор с тем же `clientId` не создаёт дубль |
| `/photo-file/{photoId}` | файл фото по временной подписанной ссылке |
| `/photo-cases`, `/photo-cases/{objectId}` | сводка фотоотчётов компании (замерщику и монтажнику недоступна) |
| `/objects/{objectId}/share` | ссылка для клиента |
| `/public/rooms/{token}` | публичная страница клиента без входа, только безопасный набор полей |

Видимость: владелец и менеджер видят все комнаты компании; замерщик и монтажник — только назначенные им. Цены видят все роли (правило `roleSeesProjectMoney`).

## Обратная связь

| Путь | Назначение |
|---|---|
| `/feedback` | GET — список: роль партнёра видит только свои обращения, админ StP — все (фильтры `status`, `type`, `orgId`); POST — новое обращение (тип, текст, контекст страницы и устройства) |
| `/feedback/summary` | число новых обращений для значка (только админ) |
| `/feedback/{feedbackId}` | GET — одно обращение (автор или админ); PATCH — статус и ответ (только админ) |
| `/feedback/{feedbackId}/photos` | POST — фото к своему обращению, до 5, JPEG |
| `/feedback-file/{photoId}` | файл фото по временной подписанной ссылке |

Отправляют владелец, менеджер, замерщик и монтажник; компанию, сотрудника, роль и время сервер ставит сам. Менеджеру StP раздел закрыт.

## Материалы

| Путь | Назначение |
|---|---|
| `/materials`, `/materials/folders`, `/materials/files` | дерево материалов |
| `/materials/files/upload-url`, `/materials/files/multipart*` | загрузка больших файлов (только admin) |
| `/materials/{materialId}`, `…/content`, `…/preview`, `…/thumbnail` | чтение и просмотр |

Роли видимости. У папки, файла и обучающего видео есть поле `roles`: `null` — все роли (внутри папки — как у папки), список из `owner`, `sales`, `measurer`, `crew`, `stp_manager` — только эти роли. Админ StP видит всё.

- `POST /materials/folders`, `POST /materials/files`, `POST /materials/files/multipart/complete` принимают `roles` (по умолчанию все роли) и `section: "video"` для обучающего видео (только видеофайл, вне папок).
- `PATCH /materials/{materialId}` с `{ roles }` меняет, кто видит (только admin). Материал внутри папки не может быть виден шире папки: ответ 400.
- `GET /materials` отдаёт роли только видимое ей; скрытое не попадает в ответ. `…/content`, `…/preview`, `…/thumbnail` скрытого — 404. Админу в каждом узле приходят `roles` и `effectiveRoles` (с учётом папок).

Новых путей нет, `GATEWAY_PATHS` не менялся.

## Как проверить маршрут

```bash
curl -s https://stp-multiframe.ru/cabinet-api/health
curl -s -o /dev/null -w "%{http_code}\n" https://stp-multiframe.ru/cabinet-api/admin/stp-managers   # 401 без входа, не 404
```
