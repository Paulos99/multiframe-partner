# Обзор и архитектура

Кабинет партнёра MultiFrame — веб-приложение для компаний, которые продают и монтируют потолки с панелями MultiFrame.
Работает как установленное приложение (PWA) в браузере на телефоне и компьютере.

Боевой адрес: **https://stp-multiframe.ru/cabinet**. Закрытый стенд владельца: https://paulos99.github.io/multiframe-partner/.

## Что умеет

| Раздел | Назначение |
|---|---|
| Проблемомер | вопросы по комнате и рекомендация по потолку: класс комфорта «сейчас» и «с MultiFrame» |
| Калькулятор | панели, крепёж, монтаж и итоговая сумма по площади |
| Проекты и комнаты | воронка: новый → замер → предложение → монтаж → завершён или отказ |
| Фотоотчёт | фото «до», «в процессе», «после»; показ клиенту по ссылке |
| Документы | PDF со сметой и профилем шума, версии |
| Обучение | методические материалы и тренажёр возражений |
| Аналитика | воронка, отказы, активность сотрудников |

Телефон клиента можно указать только с этапа «Замер» (до него в карточке поля нет).

## Роли

Подробная таблица прав — в [README.md](README.md#роли-и-права). Кратко: `admin` (сотрудник StP), `owner`, `sales`, `measurer`, `crew`
(компания-партнёр) и `stp_manager` (внутренний менеджер StP: только обучение и ссылки на инструменты).
Замерщик и монтажник не видят цен: их вырезает сервер.

## Архитектура

```
Браузер (PWA, React) ──HTTPS──▶ внешний прокси ──▶ контейнер web (nginx)
                                                    ├─ /cabinet/      статика
                                                    └─ /cabinet-api/  ──▶ контейнер api (Node.js 22, apps/api/server.mjs)
                                                                            └──▶ S3-совместимое хранилище
                                                                                   platform-v2.json    все данные платформы
                                                                                   analytics-events.json события
                                                                                   photos/<компания>/<комната>/<id>.jpg (и _t.jpg)
                                                                                   docs/<компания>/<комната>/<id>.pdf
                                                                                   training/<компания>.json
```

На стенде владельца то же приложение работает иначе: статика на GitHub Pages, API — облачная функция Yandex Cloud
за API-шлюзом ([API_ROUTES.md](API_ROUTES.md)), данные — в Object Storage. Код у обоих вариантов один.

| Каталог | Что внутри |
|---|---|
| `apps/web` | интерфейс: React 19, Vite 6, PWA |
| `apps/api` | API: `handler(event)` для облачной функции и `server.mjs` для обычного сервера |
| `packages/shared` | общий код: роли, права, видимость цен, обучение, отказы |
| `deploy` | Dockerfile, nginx, `release.sh`, `rollback.sh` |
| `infra` | развёртывание стенда владельца (вам не нужно) |
| `docs/handover` | эта документация |

## Данные

Все данные платформы — один JSON-документ плюс отдельные объекты для фото и PDF. Подключение другой базы описано в [DATA_LAYER.md](DATA_LAYER.md).
Сессия — токен JWT на 12 часов; смена пароля и сброс завершают старые сессии.

## Демо и боевой режим

На боевом сервере демо отключено: сборка с `VITE_DISABLE_DEMO=1`, `DEMO_SEED` не задан. Демо-доступы к стенду лежат в закрытом файле
у владельца (в репозитории паролей нет).
