# Выпуск по метке

Принцип: на боевой сервер попадает только метка `vX.Y.Z` на ветке `main`. Ветки, неотмеченные коммиты и правки на сервере не принимаются.

## Что происходит при создании метки

Рабочий процесс `.github/workflows/release.yml` (имя «Выпуск (по метке vX.Y.Z)») на метку `v*.*.*`:

1. проверяет, что метка лежит на `main`;
2. ставит зависимости, запускает проверку стиля, типов и тесты API и интерфейса;
3. собирает статику под `/cabinet` (с `VITE_DISABLE_DEMO=1`);
4. публикует выпуск на GitHub: архив `multiframe-cabinet-vX.Y.Z.tar.gz` и контрольная сумма `.sha256`.

Если любая проверка красная, выпуск не публикуется.

## Нумерация

| Метка | Когда |
|---|---|
| `v1.3.1` | исправление, действий от команды нет |
| `v1.4.0` | новая возможность |
| `v2.0.0` | нужны действия команды: новые переменные, перенос данных |

## Что команда получает вместе с меткой

Сообщение владельца: номер метки, что изменилось, нужны ли новые переменные окружения (добавляются в `deploy/.env` **до** установки)
и меняется ли формат данных (тогда сначала копия данных, [BACKUPS.md](BACKUPS.md)).

## Установка и откат

```bash
./deploy/release.sh v1.3.0     # установка
./deploy/rollback.sh           # откат на предыдущую метку
./deploy/rollback.sh v1.2.0    # откат на указанную метку
```

Подробности и проверки скрипта — в [DEPLOY.md](DEPLOY.md).

## Проверка после установки

1. `https://stp-multiframe.ru/cabinet/version.json` отвечает номером метки.
2. `https://stp-multiframe.ru/cabinet-api/health` отвечает `"ok":true`.
3. Вход под администратором и под владельцем партнёра; открыть проект, комнату, фотоотчёт.
4. Замерщик и монтажник не видят цен.
5. Пункты из [SECURITY_CHECKLIST.md](SECURITY_CHECKLIST.md), которые зависят от изменений выпуска.
