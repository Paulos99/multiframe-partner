# Кабинет партнёра MultiFrame: документация для передачи

Адрес боевого сервиса: **https://stp-multiframe.ru/cabinet**

Этот набор документов нужен команде, которая размещает сервис на своём сервере и подключает свою базу данных.
Код сервиса вы **не правите**: изменения вносит владелец через репозиторий `Paulos99/multiframe-partner`,
вы получаете проверенный выпуск (метку `vX.Y.Z` на ветке `main`) и устанавливаете его одной командой.

> **Важно про базу данных.** В коде нет подключения к YDB или к какой-либо SQL-базе. Все данные платформы хранятся
> одним JSON-документом в S3-совместимом хранилище (сейчас Yandex Object Storage), фотографии и PDF — отдельными
> объектами в том же бакете. Как заменить это на PostgreSQL и любое S3-хранилище — в [DATA_LAYER.md](DATA_LAYER.md).

## Архитектура

```
Браузер (PWA, React) ──HTTPS──▶ nginx ─┬─ /cabinet/      статика (HTML, JS, service worker)
                                       └─ /cabinet-api/  ──▶ API (Node.js, apps/api/server.mjs)
                                                               │
                                                               └──▶ S3-совместимое хранилище
                                                                      platform-v2.json (все данные)
                                                                      analytics-events.json (события)
                                                                      photos/<компания>/<объект>/<id>.jpg
                                                                      docs/<компания>/<объект>/<id>.pdf
                                                                    (бакет материалов — отдельный)
```

- `apps/web` — интерфейс: React 19, Vite 6, PWA (Workbox). Работает по базовому пути `/cabinet/` (настраивается).
- `apps/api` — API: один обработчик `handler(event)`. Он же работает как облачная функция Яндекса (стенд владельца)
  и как обычный HTTP-сервер (`server.mjs`, ваш вариант).
- `packages/shared` — код, общий для интерфейса и API: роли, права, расчёт видимости цен, воронка аналитики.
- `deploy` — Dockerfile, настройки nginx, скрипты установки и отката.
- `infra` — скрипты развёртывания на стенд владельца в Yandex Cloud (вам не нужны).

## Роли и права

| Роль | Кто это | Что видит и может |
|---|---|---|
| `admin` | сотрудник StP | все компании и партнёры, создание/удаление партнёров, сброс паролей, аналитика, методические материалы (правка) |
| `owner` | владелец компании-партнёра | своя компания: настройки и цены, сотрудники, все объекты компании, фотоотчёты, аналитика компании |
| `sales` | менеджер | объекты компании, расчёты и стоимость, ссылки для клиента |
| `measurer` | замерщик | свои назначенные объекты; **цен не видит** (цены вырезаются на сервере) |
| `crew` | монтажник | назначенные объекты, материалы, фото; **цен не видит** |

Права проверяются на сервере в каждом обращении (`apps/api/index.js`: `requireAuth`, `assertRole`, `objectVisibleTo`).
Скрытие цен для замерщика и монтажника выполняется на сервере (`estimateForRole`), а не только в интерфейсе.

## Модули

- **Вход и сессии** — вход по логину и паролю, токен JWT на 12 часов, блокировка после серии неверных паролей.
- **Проблемомер** и **калькулятор** (`apps/web/public/calculator`) — расчёт комнаты и стоимости потолка.
- **Объекты и проекты** — карточки заказов, статусы, группировка комнат по проектам, PDF-документы.
- **Фотоотчёт** — фото «до / в процессе / после», подписанные временные ссылки, показ клиенту.
- **Ссылка для клиента** — публичная страница `/public/rooms/<токен>` без входа, только безопасный набор полей.
- **Материалы и обучение** — методические материалы (папки, файлы, видео), тренажёр.
- **Аналитика** — события использования, воронка, сводка для админа и владельца.
- **Демонстрационный режим** — переключатель ролей для показа (`?demo=1`). **В боевой сборке отключён**
  (`VITE_DISABLE_DEMO=1`), демо-данные на сервере не создаются (`DEMO_SEED` не задан).

## Что поддерживается из коробки

- Размещение по любому базовому пути (`VITE_BASE`), по умолчанию для вас — `/cabinet`.
- Адрес API задаётся при сборке (`VITE_API_URL`): полный адрес или относительный путь `/cabinet-api`.
- Автообновление: интерфейс сверяет номер сборки (`version.json`) и обновляется сам, в том числе под `/cabinet`.
