# Концепция воронки «Путь клиента»

Ветка `cursor/funnel-compact-rows`. Реализация по этой концепции в том же PR. Павел: вливать в main после зелёного CI.

## 1. Что сейчас сломано (почему «мало что понятно»)

| Симптом | Причина |
|---|---|
| Шапка этапа «Калькулятор» = **0 / 0%**, а внутри шаги **8, 0, 8, 8, 0** | Число этапа бралось из **последнего** шага группы (`share`). «Поделился» = 0 → шапка 0, хотя до калькулятора дошли. |
| Проценты **800%, 333%** | Процент шага = `текущий / предыдущий` **без потолка**. Если предыдущий шаг 1, а текущий 8 → 800%. База ещё и прыгает между «комнатами» и «проходами». |
| «Ввёл параметры» = 0 при «Получил расчёт» = 8 | Шаги считались **независимо** по сырым событиям. Событие `calc_input` часто не пишется, а `calc_done` пишется → воронка не монотонна. |
| Минусы **«−2»** между строками | Техническая дельта без слов; непонятно, что именно «минус». |
| Строки разной ширины (на весь экран / узкая «Калькулятор») | Ширина карточки = процент от первого этапа. Визуально «криво», проценты читаются как размер, а не как число. |
| Смешение единиц | «Комната / Замер / Монтаж» — **комнаты**; «Проблемомер / Калькулятор» — **уникальные проходы** (`sessionId`). В одной лестнице без подписи это выглядит как ошибка. |

События аналитики **пока не несут `roomId`**, только `sessionId` и метаданные объекта. Поэтому «строго только комнаты» на инструментах сейчас невозможно без доработки трекинга.

## 2. Модель (предложение)

### Единица учёта

- **Цель:** уникальная **комната** за выбранный период.
- **Сейчас:**
  - этапы на статусах комнаты (**Комната, Замер и КП, Монтаж, Отказ**) — считаем **комнаты**;
  - этапы инструментов (**Проблемомер, Калькулятор, Предложение**) — считаем **уникальные проходы** (один `sessionId` = один проход) и **явно подписываем** «проходы»;
  - внутри инструмента шаги **монотонны**: дошёл до шага N ⇒ засчитан и на всех шагах 1…N;
  - следующий шаг после утверждения: писать `roomId` в события → все этапы перевести на комнаты без смены экрана.

### Шесть этапов + отказ

| # | Этап | Что значит «дошли» (число в шапке) | Шаги внутри (монотонно) |
|---|---|---|---|
| 1 | **Комната** | Комнаты, созданные в периоде | «Добавил комнату» |
| 2 | **Проблемомер** | Проходы, где хотя бы открыли Проблемомер | Открыл → Прошёл опрос → Услышал результат → Посмотрел панель |
| 3 | **Калькулятор** | Проходы, где хотя бы открыли калькулятор | Открыл → Ввёл параметры → Получил расчёт → Скачал PDF → Поделился* |
| 4 | **Предложение** | Проходы/события «предложил звукоизоляцию» | Предложил → Клиент согласился |
| 5 | **Замер и КП** | Комнаты со статусом ≥ «замерён» | Назначил замер → Замер проведён → Отправил КП → Клиент принял |
| 6 | **Монтаж** | Комнаты со статусом ≥ «монтаж» / завершено без отказа | Монтаж назначен → Выполнен → Завершено |
| — | **Отказ** | Закрытые комнаты с записью отказа за период | Доли по причинам отказа (если есть) |

\*«Поделился» сейчас пишется с инструментом `problemomer`; в новой модели шаг остаётся в калькуляторе как «поделились результатом», но считается по событию `share` (любой tool), и не может обнулить шапку этапа.

### Формулы

Пусть \(C_i\) — число этапа \(i\) (после монотонии внутри этапа), \(C_1\) — число «Комната» (или первый ненулевой этап-база).

- **От предыдущего:** \(\min(100\%,\ \mathrm{round}(C_i / C_{i-1} \cdot 100\%))\), подпись: «от предыдущего этапа».
- **От начала:** \(\min(100\%,\ \mathrm{round}(C_i / C_1 \cdot 100\%))\), подпись: «от начала».
- **Потери:** если \(C_{i-1} > C_i\), между карточками: **«Не дошли до следующего этапа: N»**, где \(N = C_{i-1} - C_i\). При \(N = 0\) подпись скрыта.
- **Шаг внутри этапа:** число проходов/комнат, дошедших до шага; % шага — **от входа в этап** (первого шага группы), потолок 100%.
- **Отказ:** доля от **всех закрытых** за период; рядом список причин (`refusalStats`).

Монотонность внутри инструмента (пример калькулятора):

```
сырые события: open×8, calc_input×0, calc_done×8, pdf×8, share×0
после «дошёл до max»: open=8, input=8, done=8, pdf=8, share=0
шапка этапа = 8 (вход = open), не 0
% «Получил расчёт» = 8/8 = 100%, не 800%
```

### Как читать (одна фраза под заголовком)

> Считаем, сколько дошло до каждого этапа за период. Процент — от предыдущего этапа и от начала. «Не дошли…» — сколько выбыло между этапами. Нажмите этап, чтобы увидеть шаги.

### Пустые состояния

- Нет комнат за период → «За период комнат пока нет» + серые карточки с «—».
- Этап 0 → карточка на месте, число 0, полоска пустая, без ложных %.
- Нет причин отказа → блок «Отказ: 0», без списка причин.

### Внешний вид

- Все 6 строк **одной ширины** (~340px на десктопе), колонкой слева/по центру блока; на ширине ≤520px — на всю ширину контейнера.
- Процент **не** меняет ширину карточки: внутри — полоска прогресса и цифры.
- Раскрытие этапа: плавная высота, без мерцания всего блока; `prefers-reduced-motion` — без анимации.
- Иерархия: название этапа → крупное число → две мелкие подписи конверсии → полоска → (при раскрытии) шаги.

## 3. Пример на цифрах

Период: ноябрь. Создано **10** комнат.

| Этап | Число | От пред. | От начала | Между этапами |
|---|---:|---:|---:|---|
| Комната | 10 | — | 100% | |
| Проблемомер | 8 | 80% | 80% | Не дошли до следующего этапа: 2 |
| Калькулятор | 6 | 75% | 60% | Не дошли до следующего этапа: 2 |
| Предложение | 4 | 67% | 40% | Не дошли до следующего этапа: 2 |
| Замер и КП | 3 | 75% | 30% | Не дошли до следующего этапа: 1 |
| Монтаж | 2 | 67% | 20% | Не дошли до следующего этапа: 1 |
| Отказ | 1 из 3 закрытых (33%) | причины: «Дорого» 1 | | |

Раскрытый «Калькулятор» (6 вошли): Открыл 6 (100%) → Ввёл 6 → Расчёт 5 → PDF 4 → Поделился 1.

## 5. Что войдёт в PR (после утверждения — влив)

1. Пересчёт: монотонные проходы в инструментах; шапка этапа = вход в этап; % с потолком 100% и подписями; потери словами.
2. Компактные одинаковые строки + отказ с причинами.
3. Подсказка «как читать»; пустые состояния.
4. Unit-тесты (в т.ч. «8 событий по 1 проходу ≠ 800%», шапка калькулятора = 8 при share = 0).
5. **Не** трогаем прод, теги, релизы. Версия 1.2.0.
