# Переменные окружения (только имена и назначение)

Значения секретов **никогда** не записываются в репозиторий, в чат и в журналы. Хранить — в файле `deploy/.env`
(права `600`, владелец — пользователь, от которого работает сервис) или в хранилище секретов вашей инфраструктуры.
Шаблон: `deploy/.env.example`.

## API (`apps/api`)

| Имя | Обязательна | Назначение |
|---|---|---|
| `JWT_SECRET` | да | ключ подписи сессий. Случайная строка не короче 32 символов (`openssl rand -hex 32`) |
| `JWT_SECRET_PREVIOUS` | нет | прежний ключ на время плановой смены `JWT_SECRET` (12 часов) |
| `ANALYTICS_ADMIN_KEY` | да | служебный ключ чтения аналитики. Независимое случайное значение |
| `PARTNERS_BUCKET` | да (в боевой работе) | бакет с данными кабинета |
| `MATERIALS_BUCKET` | нет | отдельный бакет методических материалов. Не должен совпадать с `PARTNERS_BUCKET`. Без него загрузка материалов отвечает 503 |
| `S3_ENDPOINT` | нет | адрес S3-совместимого хранилища (по умолчанию `https://storage.yandexcloud.net`) |
| `S3_REGION` | нет | регион (по умолчанию `ru-central1`) |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | да | ключи доступа к хранилищу. Права — только на нужные бакеты |
| `S3_FORCE_PATH_STYLE` | нет | `1` для MinIO и подобных хранилищ |
| `YC_ACCESS_KEY_ID`, `YC_SECRET_ACCESS_KEY`, `YC_REGION` | нет | прежние имена тех же значений (работают, если `S3_*` не заданы) |
| `PLATFORM_KEY`, `ANALYTICS_KEY` | нет | имена объектов в бакете (по умолчанию `platform-v2.json`, `analytics-events.json`) |
| `PLATFORM_FILE` | нет | локальный файл вместо бакета. Только для разработки: нет защиты от одновременной записи, фото не хранятся |
| `CORS_ORIGIN` | да | разрешённые адреса сайта через запятую. Для боевого: `https://stp-multiframe.ru`. По умолчанию подставляется адрес стенда владельца — для вас это неверно |
| `ADMIN_BOOTSTRAP_LOGIN`, `ADMIN_BOOTSTRAP_PASSWORD`, `ADMIN_BOOTSTRAP_NAME` | только первый запуск | создают единственного администратора в пустом хранилище. Пароль не короче 10 символов. После входа удалить |
| `DEMO_SEED` | нет | `1` создаёт демо-кабинеты с известными паролями. **На боевом сервере не задавать.** Без значения демо поднимается только без бакета и вне `NODE_ENV=production` |
| `ALLOW_DEMO_RESET` | нет | `1` разрешает админу сбрасывать данные к демо (`POST /admin/demo/reset`). **Только стенд** |
| `SHARE_LINK_TTL_DAYS` | нет | срок жизни ссылки для клиента в днях. Без значения срока нет; для боевого рекомендуем 30 |
| `BCRYPT_COST` | нет | стоимость хеширования паролей, 10–14 (по умолчанию 12) |
| `MAX_BODY_BYTES` | нет | предел размера запроса (по умолчанию 6 000 000) |
| `NODE_ENV` | рекомендуется | `production` (в образе уже задан) |
| `PORT`, `HOST`, `TRUST_PROXY` | нет | для `server.mjs`: порт (8080), адрес (127.0.0.1; в образе 0.0.0.0), `1` — брать адрес клиента из `X-Forwarded-For` (только за своим прокси) |

## Сборка интерфейса (`apps/web`)

Задаются при сборке, внутрь кода секреты не попадают (всё, что начинается с `VITE_`, видно любому посетителю).

| Имя | Назначение |
|---|---|
| `VITE_BASE` | базовый путь сайта. `/cabinet` для вас; `/` — корень домена |
| `VITE_API_URL` | адрес API: `/cabinet-api` (тот же домен) или полный адрес. Пусто — локальный режим без сервера |
| `VITE_DISABLE_DEMO` | `1` — убрать демо-режим из сборки (боевая сборка) |
| `BUILD_ID` | номер сборки для автообновления (`version.json`). Скрипт установки подставляет имя метки |
| `VITE_YM_ID` | счётчик Яндекс.Метрики (по желанию; баннер согласия появляется только если задан) |
| `VITE_ANALYTICS_INGEST_URL` | внешний приёмник событий (по желанию) |
| `VITE_DEMO_MODE` | `true` включает демо во всей сборке. Не использовать в боевой сборке |

## Скрипты установки (`deploy/`)

| Имя | Назначение |
|---|---|
| `WEB_PORT` | порт на локальном адресе, куда внешний прокси направляет `/cabinet` и `/cabinet-api` (8081) |
| `ENV_FILE` | другой путь к файлу настроек (по умолчанию `deploy/.env`) |
| `REQUIRE_SIGNED_TAG=1` | требовать подпись метки выпуска (`git verify-tag`) |
| `FORCE=1`, `NO_AUTO_ROLLBACK=1` | переустановка той же метки; отключение автоматического отката при неудачной проверке |
