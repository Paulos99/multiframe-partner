# Проекты — статус интеграции

Обновлено: 18 октября 2026.

Модель без новой сущности: проект — клиент и адрес, комната — прежний объект с `roomName`. Объектов без проекта в новой записи не бывает.

## Поведение

- `POST /objects` без `projectId` создаёт проект той же компании (имя клиента, иначе адрес) и привязывает комнату. Права на сам `POST /projects` не расширялись: владелец и менеджер пишут проекты, замерщик и монтажник по-прежнему нет. Замерщик создаёт комнату, и проект появляется вместе с ней.
- Пустой `projectId` у уже привязанной комнаты — 400. Перенос в другой проект своей компании — обычный `PATCH` объекта.
- Старые объекты без `projectId` сами не переписываются. Их забирает скрипт миграции.
- В кабинете один список в разделе объектов: проект, внутри комнаты. Отдельной вкладки «Проекты» у компании нет. У STP вкладка остаётся, своего списка объектов там нет. Поиск и фильтр по статусу прежние. «Создать» делает проект и первую комнату, внутри есть «Добавить комнату». В карточке сохранения можно выбрать существующий проект или новый.

## Миграция

`node apps/api/scripts/link-objects-to-projects.mjs --dry-run`

Env: `API_BASE`, `MF_STAFF_LOGIN`, `MF_STAFF_PASSWORD` (владелец или менеджер одной компании). Скрипт пишет только `POST /projects` и `PATCH` объекта, после записи перечитывает результат. `prj_f20um0dq5eqq` и уже привязанные объекты не меняет. На боевой API не запускать, пока Павел не попросит и пока не задеплоен фикс кэша.
