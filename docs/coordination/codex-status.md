## Занятые участки

### В работе: понятная история объекта

Подтверждение разработчику: новые зависимости не нужны. Codex не меняет `package.json`, lock-файлы, README, API и скрипт тестового объекта. По сообщению разработчика, агент тестового объекта ограничен новым скриптом, README и возможным `package.json`; с компонентами карточки пересечений нет. Это подтверждение согласованных границ, не результат просмотра текущего diff PR агента.

Границы согласованы в разговоре: агент тестового объекта меняет API и данные, Codex — только отображение истории. Заняты Codex: `apps/web/src/partner/ObjectsPanel.tsx`, новые `ObjectHistory.tsx`, `ObjectHistory.module.css`, `objectHistory.ts`, `objectHistory.test.ts` в той же папке. Сервер, материалы, калькулятор и общие стили не затрагиваются. Результат: понятные события с датой и автором, три последних сразу, остальные раскрываются. Неизвестные события не показывают сырые технические данные. После проверки будет опубликован результат и файлы освобождены.

Сейчас незавершённых изменений кода у Codex нет. Файлы исправления освобождены. Этот файл — отчёт Codex; отдельный отчёт другого исполнителя позволит избежать взаимного перезаписывания.

### Подтверждение границ для материалов

Codex не меняет `apps/web/src/partner/MaterialsPanel.tsx`, `materialsClient.ts`, `MaterialStubView.tsx`, `apps/api/materialsRoutes.js`, `materialsLib.js`, а также связанные тесты и стили обучения. Эти участки свободны для задачи Грокбота. Общие файлы `apps/api/index.js`, `packages/shared/partner.ts`, `CabinetScreen.tsx`, `partner.module.css` и `infra/deploy_yc.py` также сейчас не заняты Codex; изменения в них требуется перечислить в отчёте исполнителя перед началом параллельных работ. Исправление доступа к документам в `index.js` и `partner.ts` уже опубликовано и должно сохраниться.

Решение по коммерческой политике: информационная заглушка «Материал готовится к публикации», без неработающей ссылки и без выдуманного содержимого. Ожидание файла от Павла не блокирует остальные четыре раздела. До согласования аудитории заглушку показывать только STP и владельцу; документ дистрибьютора не открывать автоматически всем сотрудникам.

## Следующая задача разработки — исполнитель не закреплён

### Актуальное уточнение: минимальная подстановка площади

По последнему сообщению разработчика, проблемомер сохраняет ответы, калькулятор подхватывает объект, а расчёт записывается в ту же карточку. Поэтому прежнее широкое предложение ниже не является объёмом следующего изменения.

После переноса материалов — только подстановка сохранённой площади при открытии калькулятора для выбранного объекта с возможностью уточнить её. В режиме размеров площадь определяется геометрией; размеры из площади не выдумываются. Перестройка заказов, версии расчётов, аналитика и остальные функции в этот минимальный дифф не входят.

Приёмка: два объекта с разной площадью открываются без подмешивания данных друг друга; уточнённый расчёт сохраняется в исходную карточку без дублей; новый расчёт без привязки не наследует предыдущую площадь. Проверить после перезагрузки. Исполнитель и точные файлы пока не закреплены; изменение ещё не реализовано.

### Ранее предложенный широкий объём — справочно, не текущая задача

Последнее решение заказчика и подтверждение в разговоре заменили ограничение «только инвентаризация»: бот «Мультифрейм партнёр» (Грокбот) отвечает за полный перенос материалов из Яндекс.Диска в Яндекс.Облако и отображение в папках обучения, при необходимости через агентов Cursor. Черновик задачи готовится, точные файлы ещё не закреплены. Codex не меняет обучение параллельно. Предложение по связке инструментов ниже остаётся отдельной, пока не принятой задачей.

Передача известных параметров из проблемомера в калькулятор с привязкой к исходному объекту. Предварительный расчёт по площади сохраняется без выдуманной геометрии и без отметки о наличии схемы.

Возможные точки изменений: `apps/web/src/App.tsx`, `apps/web/src/partner/PartnerContext.tsx`, `apps/web/src/partner/SaveObjectCard.tsx`, `apps/web/src/partner/cabinetCalc.ts`, встроенный калькулятор. Это ориентиры, не подтверждённая блокировка файлов.

Критерии: площадь и тип помещения переносятся там, где поддерживаются; результат сохраняется в исходный объект без дубля; смена объекта не подмешивает прежние данные; сохранение проверено после перезагрузки; размеры не выводятся из площади.

## Очередь после связки

1. Заказ с несколькими помещениями с сохранением старых записей.
2. Версии исходных данных расчёта и сметы, общее предложение по выбранным версиям помещений.
3. Отдельные ответственные по этапам, следующее действие и срок.
4. Экраны ролей, понятная история, согласованные статусы и подписи.
5. Отделение демособытий; аналитика активности отдельно от конверсии заказов.
6. Проверка полного пути трёх помещений, доступов между компаниями, назначения монтажнику и мобильного интерфейса.

## Уточнения по коду

- Открытие калькулятора для существующего объекта уже предусмотрено.
- Расчёт по площади сейчас исключён из прикрепления результата.
- PDF имеют версии; текущая смета объекта заменяется.
- Открытия инструментов ограничены по частоте регистрации: отношение всех расчётов к открытиям не является конверсией.
- Хранилище может содержать реальные записи: сброс и удаление демоданных не выполнялись.

Общий доступ через репозиторий подтверждён; доступ Грокбота к папке рабочего стола не подтверждён. До подтверждения доставки нельзя считать, что задача принята исполнителем.
