# План доработки на 18 октября 2026

Единый рабочий план по поручению Павла. Участники: Павел — заказчик; ChatGPT/Codex — продуктовая логика, выделенные доработки и проверка; Грокбот «Мультифрейм партнёр» — разработчик, управление агентами Cursor и облаком. Cursor — инструмент разработчика.

## Реалистичный результат дня

Довести текущий процесс одной комнаты до удобного тестирования: понятная история, проверенные документы монтажника, подстановка площади и доступные материалы обучения. Заказ с несколькими комнатами и общее предложение остаются следующим этапом: сегодня не обещаем их реализацию и не начинаем перестройку модели данных.

## Параллельные направления

| Ответственный | Работа | Готово, когда |
|---|---|---|
| ChatGPT/Codex | Подставить сохранённую площадь при открытии калькулятора для объекта, разрешить уточнение | Два объекта не смешиваются; новый расчёт не наследует чужую площадь; геометрия определяет площадь в режиме размеров; существующее сохранение расчёта не сломано |
| Грокбот | Завершить перенос четырёх доступных разделов в приватное облако и подключить папки к обучению через агента | Реестр исходников, уникальных файлов, дублей и ошибок; список подключён к кабинету; небольшой и крупный файл открываются с разрешённой ролью; неподходящая роль не получает внутренние материалы |
| Грокбот через текущего агента | Завершить скрипт тестового объекта и проверку спецификации | Реальный PDF спецификации открывается монтажнику без цен; смета и чужие объекты недоступны; существующие данные сохранены |

Коммерческая политика — информационная заглушка для STP и владельца, без кнопки. Новый файл от Павла не блокирует остальные разделы. Общая загрузка по последнему устному отчёту ещё не закончена; прогноз времени не является подтверждением результата.

**Грокбот, материалы:** `apps/web/src/partner/MaterialsPanel.tsx`, `materialsClient.ts`, `MaterialStubView.tsx`, `apps/api/materialsRoutes.js`, `materialsLib.js`, связанные тесты. Код калькулятора можно использовать для запуска, но не менять параллельно с задачей подстановки. Если скрипту нужна правка самого калькулятора, этот конкретный участок выполняется последовательно.

История объекта опубликована коммитом `ce01f18`, локально проверена. Грокбот проверяет её на сайте; Codex берёт только обнаруженные дефекты в собственных файлах истории. Задачи не ждут взаимных устных отчётов: рабочие границы заданы здесь.

## Последовательность и бюджет времени

1. Сейчас параллельно: Codex делает подстановку; Грокбот завершает загрузку и скрипт. Для подстановки ориентир 60–90 минут вместе с локальными проверками, не гарантия срока.
2. После реестра загрузки: агент Грокбота подключает материалы. Резерв 2–3 часа на интеграцию, выдачу крупных файлов и права; оценка уточняется по фактическим файлам и результату скрипта.
3. Последние 60 минут доступной работы — только сборка, развёртывание и проверки опубликованного сайта, без новых функций. Если перенос задерживается, незавершённая часть остаётся явно отмеченной, существующее обучение сохраняется.

## Приёмка дня

- История: три последних события, автор и дата, раскрытие/сворачивание, сброс раскрытия при смене объекта.
- Калькулятор: разные площади двух объектов, редактирование, отсутствие переноса старой площади в новый объект, сохранение существующего сценария.
- Монтажник: свой объект и спецификация доступны; цены, смета и чужой объект недоступны.
- Материалы: числа и пропуски сверены; маленький и большой файл открываются из опубликованного кабинета; права проверены на сервере.
- Для каждой задачи отдельно: реализовано → проверено локально → проверено на сайте. Зелёный деплой не заменяет проверку сценария.
