# Общая координация MVP MultiFrame

Актуальное разделение разработки: [план на сегодня](today-plan.md). Этот план заменяет прежние предложения о неназначенных задачах; работа идёт параллельно без ожидания взаимных отчётов.

По решению заказчика от 18 октября 2026 основное место обмена между ChatGPT/Codex и Грокботом — эта папка в репозитории. Папка рабочего стола содержит только копию раннего отчёта и не является актуальным источником.

## Отчёты участников

- [Codex: результат, свободные участки, следующая задача](codex-status.md)
- Для ответа Грокбота предусмотрен отдельный файл `grokbot-status.md`; он пока не создан, приём задачи не подтверждён.

## Порядок работы

1. Перед задачей получить свежую основную ветку и прочитать отчёты.
2. В собственном отчёте указать принятую задачу, предполагаемые файлы и критерии готовности. Не изменять отчёт другого участника.
3. Если участки пересекаются, сначала согласовать разделение через отчёты; предложение задачи не означает её принятие.
4. После завершения указать коммит, выполненные проверки, ограничения и состояние развёртывания. Освободить файлы явно.
5. Перед публикацией снова сверить основную ветку; не применять принудительную отправку и не затирать чужие изменения.

## Текущее состояние

- Исправление доступа монтажника к документам опубликовано, шесть проверок прошли. Развёртывание ещё не подтверждено.
- Последнее решение заказчика и подтверждение в разговоре: бот «Мультифрейм партнёр» (Грокбот), управляющий агентами Cursor, отвечает за полный перенос партнёрских материалов из Яндекс.Диска в Яндекс.Облако и отображение файлов в папках раздела «Обучение». Это заменяет прежнее ограничение «только инвентаризация». Черновик задачи агенту готовится; точные файлы и границы изменений ещё не закреплены. Codex не изменяет раздел обучения параллельно.
- Ранее предложенная связка проблемомера и калькулятора отдельно не принята; исполнитель этой задачи пока не закреплён.
- Следующий общий этап: заказ с помещениями и версии расчётов; затем передача между ролями и проверка рабочего сценария.

Обмен происходит при чтении свежей версии репозитория. Автоматическая доставка сообщений и фоновое наблюдение этим файлом не обеспечиваются.
