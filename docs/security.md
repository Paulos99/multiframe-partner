# Ключи API и ротация

`JWT_SECRET` и `ANALYTICS_ADMIN_KEY` обязательны. Генерируйте независимые случайные
значения (не менее 32 случайных байтов), сохраняйте в GitHub Secrets с теми же именами.
Не помещайте их в репозиторий, клиентские VITE-переменные или логи.
Workflow передаёт их только шагу деплоя API. При пустом/отсутствующем значении оба
скрипта деплоя сохраняют значение из окружения последней версии функции;
если обязательного ключа нет ни там, ни в окружении деплоя, деплой завершается ошибкой.
Чтение выполняется через [GetVersionByTag](https://yandex.cloud/en/docs/functions/functions/api-ref/Function/getVersionByTag)
с тегом `$latest`; сервисному аккаунту нужно право чтения версий.

## Плановая ротация без массового выхода

1. Сохраните старый случайный ключ в GitHub Secret `JWT_SECRET_PREVIOUS`,
   новый — в `JWT_SECRET`. Уберите переменную Actions `JWT_SECRET_PREVIOUS_CLEAR`,
   если она осталась после прошлой ротации. Запустите деплой API и клиента.
2. Новые токены подписываются текущим ключом; `kid` содержит только короткий SHA-256
   отпечаток. API принимает оба ключа, включая старые токены без `kid`.
   `/auth/me` обновляет токен предыдущего ключа, клиент сохраняет его.
3. Через 12 часов после прекращения выдачи токенов старым ключом удалите GitHub Secret
   `JWT_SECRET_PREVIOUS`, задайте Actions variable `JWT_SECRET_PREVIOUS_CLEAR=true`
   и повторите деплой. Это удалит ключ и из окружения новой версии функции.
   После успешного деплоя уберите переменную очистки. Простое удаление Secret
   не удаляет облачное значение, потому что деплой сохраняет существующие значения.

Для ручного деплоя те же настройки передаются через переменные окружения.
`ANALYTICS_ADMIN_KEY` заменяется независимо, без периода совместимости.

## Первичное устранение утечки

Ранее использовавшийся вычислимый JWT-ключ и опубликованный ключ аналитики считаются
скомпрометированными. Замените оба новыми случайными значениями; **не сохраняйте
скомпрометированный ключ в PREVIOUS**. При этом старые сессии потребуют входа заново.
Ротация с PREVIOUS предназначена для последующих смен нескомпрометированных ключей.
Проверьте, что gateway вызывает новую версию, и исключите вызов старых уязвимых версий
через оставленные теги или прямые интеграции.

## Локальная разработка

API не имеет встроенного секретного ключа: задайте `JWT_SECRET` и
`ANALYTICS_ADMIN_KEY` в окружении локального процесса. `CORS_ORIGIN` по умолчанию
равен `https://paulos99.github.io`; для разработки задайте origin локального клиента,
например `http://localhost:5173`. Деплой принимает переопределение через env
`CORS_ORIGIN` (в GitHub Actions — одноимённая variable). E2E-сервер задаёт свой origin.
