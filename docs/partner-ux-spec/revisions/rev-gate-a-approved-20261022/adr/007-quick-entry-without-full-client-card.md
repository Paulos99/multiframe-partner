# ADR-007 — Быстрый вход: консультация/расчёт без полной карточки клиента

- **Статус:** Accepted (`rev-gate-a-approved-20261022`)
- **Дата:** 2026-10-22

## Контекст

Draft-1 требовал почти для всего проект+комнату до PM/Calc. На практике sales часто начинает консультацию или ориентировочный расчёт **до** известного адреса/телефона (встреча, звонок, «прикинуть по площади»). Жёсткий барьер создавал либо отказ от инструмента, либо silent orphan-объекты (разрыв B1/C1).

В draft-2 диаграмма D3 §5.3 ошибочно ставила bind **до** режима расчёта (`SessionDraft → BindThenSave → AreaMode`), расходясь с §3b.

## Решение

### Быстрый сценарий (quick-entry) — канонический порядок

1. **Открыть** инструмент (PM / Calc) **без** обязательных адреса, телефона.  
2. **Получить результат** во **временном** session draft (не persist как безымянный Project/Room).  
3. **Save** → система требует:
   - **Выбрать** существующий проект+комнату **или**  
   - **Создать** проект с минимальными полями (ярлык / «Черновик + дата» + имя комнаты).  
4. **Confirm persist** в выбранную/новую комнату.  

Запрещено: bind **до** результата; save в «объект без проекта»; безымянный проект; silent orphan.

### Минимальные поля при создании с quick-entry

| Момент | Обязательно | Можно отложить |
|--------|-------------|-----------------|
| Старт PM/Calc | роль, org | клиент, телефон, адрес |
| Первый persist | проектный ярлык (имя клиента **или** явный «Черновик YYYY-MM-DD») + имя комнаты | телефон, адрес, город — с пометкой «дополнить» |
| Перед confirm_sent КП | **способ передачи** КП (канал/контакт); телефон и адрес **не** обязательны всегда | полнота карточки клиента |

### Связь с типами расчёта (ADR-005)

Quick-entry чаще ведёт к **preliminary**; переход к detailed — после persist в комнату (или в той же сессии после bind). Оба типа после save принадлежат комнате.

## Отвергнутые альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| Всегда полная карточка до любого инструмента | Блокирует консультацию; провоцирует выдуманные данные |
| Silent create object при save из Tools | Orphans, дубли, потеря иерархии |
| Persist без имени («безымянный») | Невозможно найти в списке; дубли плодятся |
| Отдельный «песочный» каталог вне проектов | Вторая ментальная модель; противоречит ADR-002 |
| Bind до расчёта (ошибка draft-2 §5.3) | Ломает основной сценарий «сначала результат, потом куда сохранить» |

## Следствия

- Home CTA: «Быстрая консультация» / «Быстрый расчёт» → tool → result → Save → pick/create → persist.  
- Golden path «новый клиент с полными данными» остаётся; quick-entry — параллельный законный путь.  
- D2: S-sales-05, S-x-05/06; D3: §3b и §5.3 согласованы.  
- Деталь валидации полей — D4/D5 (Gate B).
