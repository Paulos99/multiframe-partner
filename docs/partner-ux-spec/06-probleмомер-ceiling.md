## 0. Назначение и границы

| Внутри D6 | Вне D6 |
|-----------|--------|
| Партнёрский путь PM в кабинете (потолочники) | Visitor-путь сайта StP (отдельный UX; то же акустическое ядро) |
| Сценарии: старт → параметры комнаты → Result → «Следующий шаг» | Pixel/screen specs (D4), API/snapshot (D5) |
| Save профиля в комнату / quick-entry bind | Изменение формул Rw/Lnw, аудио-стемов, field anchors |
| Кабинетные CTA с project/room context | Заявка/lead на stp-multiframe.ru как **единственный** next step |

**Не ломаем:** акустическое ядро, цепочку Result (нормы → сейчас → MultiFrame → уникальность → следующий шаг), evidence pack, запрет lab-гарантий и price-first тона из PRODUCT_SPEC.

**Не ломаем §8 / Gate A:** Project→Rooms; quick-entry `tool → result → Save → bind → persist`; Deal/Quote SoT не живёт внутри PM.

## 1. Продуктовые принципы сегмента

| # | Принцип | Следствие |
|---|---------|-----------|
| P1 | Клиент пришёл за **натяжным потолком** | Старт PM не требует жалобу на шум и не звучит как «проверить, мешает ли шум» |
| P2 | PM **формирует потребность** в ЗИ | Result показывает комфорт «сейчас / с MultiFrame» как аргумент под полотном |
| P3 | Вопрос **типа потолка** не в основном партнёрском пути | В модель уходит пресет сегмента «натяжной» / скрытые дефолты ([ADR-005](./adr/005-ceiling-segment-presets-pm-calc.md)) |
| P4 | «Следующий шаг» = действия с **проектом/комнатой** | Не только StP lead; см. §5 |
| P5 | PM **опционален** | Можно пропустить и открыть calc (D7) |
| P6 | Одно ядро, два UX | Кабинет ≠ публичный Result CTA; shared model/audio/charts |
| P7 | Кто может | **sales, owner, measurer** ведут PM ([D2a](./02a-responsibility-matrix.md)); crew — только чтение профиля |

## 2. Кабинет vs публичный UX (одно ядро)

| Аспект | Публичный (PRODUCT_SPEC) | Кабинет (этот документ) |
|--------|--------------------------|-------------------------|
| Аудитория | Посетитель объекта / сайта | Сотрудник потолочной компании с клиентом |
| Старт | «Начать» без роли | Из комнаты / Tools / «Быстрая консультация» (quick-entry) |
| Вопрос «планируемый потолок» | Есть в Room | **Нет** в основном пути; пресет `stretch` |
| Result «Следующий шаг» | Calc URL + консультация StP + сводка + restart | Save в комнату · Calc · Bind · К проекту · (вторично: копия сводки клиенту) |
| Persist | Session / lead handoff | Acoustic **profile document** на Room |
| Контекст | Нет projectId | `projectId` + `roomId` известны **или** появятся на Save→bind |

**Правило:** менять можно chrome, CTA, порядок входа и omit полей сегмента. Нельзя менять смысл классов А/Б/В, felt vs official, каналы воздух/удар, honesty-дисклеймеры, запрет «Д» / lab certificate.

## 3. Пресет сегмента → параметры модели

Модель по-прежнему нуждается в параметрах потолка / drum-эффекта. Источник в кабинете:

| Параметр модели | Источник в партнёрском пути |
|-----------------|----------------------------|
| Тип отделки потолка / drum | **Пресет:** натяжной под MultiFrame (`plannedCeiling = stretch`) |
| Тип дома, перекрытие, толщина, тип комнаты, площадь, стадия, соседи, цель использования | Анкета Room (кабинетный порядок — §4) |
| Пол сверху | **Assumption:** в кабинете не спрашиваем (как в актуальном visitor UI); модель = `unknown` → conservative ordinary floor |
| Год постройки | Не в MVP (как PRODUCT_SPEC) |

Если sales **явно** знает нестандартный потолок (уже ГКЛ / штукатурка) — **Assumption:** вторичный «расширенный режим» / правка профиля после save, **не** шаг основного пути. Не утверждено заказчиком.

## 4. Сценарии

### S-pm-01 — PM из комнаты (полный путь)

| Поле | Содержание |
|------|------------|
| **Начало** | Открыта комната проекта; клиент на встрече/звонке; хочет натяжной. |
| **Результат** | На комнате сохранён акустический профиль; пользователь в той же комнате (или calc с тем же `roomId`); Deal.stage может стать `assessed`, если ещё раньше; **outcome не трогаем**. |
| **User** | Комната → «Диагностика / Проблемомер» → (опц. короткий Start) → анкета Room → Processing → Result → «Сохранить профиль в эту комнату» → далее CTA §5. |
| **System** | Подставляет пресет потолка; считает модель тем же ядром; пишет profile + answers к `roomId`; сохраняет `projectId`; не создаёт orphan; не ставит Deal.outcome. |
| **Состояния** | Room: Draft/Measured + profile; Deal: `offered`→`assessed` (если был contact/offered) — **A-09 proposed:** авто-advance stage ≥ `assessed` при первом успешном save профиля ([D5 §3.1](./05-data-model-contracts.md)); outcome/pause только вручную. |
| **Данные** | Room profile document, answers snapshot, derived classes/Δ (для UI); без accept на Quote. |
| **Ошибки** | Сеть mid-save → retry / outbox; модель упала → Result error + «повторить расчёт» без потери answers; offline → локальный draft профиля, pendingSync на комнате. |
| **Ответственные** | Sales / owner / measurer — R; owner — A. |
| **AC** | После save открыта **та же** комната; в UI нет вопроса «какой потолок планируете» в основном пути; CTA Result не единственно «заявка StP»; возврат «Назад» с Result не переигрывает Processing. |

### S-pm-02 — Quick-entry «Быстрая консультация»

| Поле | Содержание |
|------|------------|
| **Начало** | Home sales/owner: адрес/телефон ещё неизвестны. |
| **Результат** | Профиль в существующем или новом проекте+комнате; нет безымянных / orphan. |
| **User** | «Быстрая консультация» → PM → Result → **Save** → E-quick-bind (выбрать/создать ярлык+комнату) → confirm persist. |
| **System** | Session draft с результатом **до** Save; bind **после** Save ([ADR-007](./adr/007-quick-entry-without-full-client-card.md)); создаёт активную Deal на новом проекте. |
| **Состояния** | SessionDraft → Save → BindModal → Saved / Abandoned (D3 §3b). |
| **Данные** | SessionDraft, Project (min), Room, profile, Deal(contact→assessed). |
| **Ошибки** | Save без bind → блок модалкой; уход без Save → confirm discard; повторный Save того же draft → та же комната. |
| **Ответственные** | Sales / owner — R. |
| **AC** | После persist есть читаемое имя в списке проектов; телефон/адрес можно дополнить позже; порядок не «сначала карточка, потом результат». |

### S-pm-03 — Пропуск PM → сразу calc

| Поле | Содержание |
|------|------------|
| **Начало** | Клиент «сразу цену» / менеджер знает аргумент без демо. |
| **Результат** | Пользователь в Calc (D7) с тем же room context или quick-entry calc; комната **без** профиля допустима. |
| **User** | Из комнаты «Рассчитать» **или** Home «Быстрый расчёт» — **без** обязательного прохождения PM. |
| **System** | Не блокирует calc отсутствием профиля; не подставляет фейковый профиль. |
| **AC** | Нет gate «сначала проблемомер»; на комнате виден empty state «профиль не собран» (информативно, не блокер calc). |

### S-pm-04 — Sales / owner сами ведут PM

| Поле | Содержание |
|------|------------|
| **Начало** | Measurer не назначен / не на смене. |
| **Результат** | Профиль сохранён; назначение measurer **не** требуется для права PM. |
| **User** | Sales или owner открывает PM (S-pm-01 или S-pm-02). |
| **System** | RBAC: роль sales/owner имеет право persist профиля; assignment measurer не отбирает это право ([D2a §1a](./02a-responsibility-matrix.md)). |
| **AC** | Нет сообщения «только замерщик может открыть диагностику». |

### S-pm-05 — Measurer дополняет / пересчитывает профиль

| Поле | Содержание |
|------|------------|
| **Начало** | Inbox «продолжить комнату»; профиль пуст или устарел после уточнения плиты. |
| **Результат** | Актуальный профиль на комнате; история предыдущих сохранений доступна (минимум: last saved at + кто). |
| **User** | Комната → PM → правки answers → Save. |
| **System** | Перезапись текущего профиля комнаты; **Assumption:** хранить ≥1 предыдущую версию answers для аудита (деталь полей — D5). |
| **AC** | projectId/roomId не меняются; Deal.outcome не сбрасывается. |

## 5. Анкета Room в кабинете (основной путь)

Порядок (кабинетный, сегмент потолочники):

1. Тип дома  
2. Тип перекрытия (filtered by house, как ядро)  
3. Толщина (buckets)  
4. Тип комнаты + площадь  
5. Стадия объекта  
6. Шумные соседи → [тип шума, если шумно]  
7. Что важнее в комнате (без бренда MultiFrame в вопросе)

**Обязательно для Далее / Result:** тип комнаты + площадь > 0.  
**Опционально / «Не знаю»:** всё остальное → model ASSUMPTION внутри ядра.

**Исключено из основного пути:**

- планируемый / текущий **тип потолка** (пресет);  
- жалоба «мешает ли шум» / сценарии «что беспокоит»;  
- роль «для себя / для клиента»;  
- этаж;  
- стены / Polyblock / год постройки.

**Start (кабинет):** короткий контекстный экран допустим («Комфорт комнаты под натяжным»), без role picker. **Assumption:** можно схлопнуть Start в одну строку над первой карточкой Room, если вход уже из комнаты с именем клиента.

**Processing:** та же церемония ядра (fullscreen, progress, rotating status); Back с Result **не** переигрывает.

**Result:** та же смысловая цепочка PRODUCT_SPEC § Result; меняется только блок «Следующий шаг» (§6).

## 6. «Следующий шаг» (кабинет) — обязательные CTA

Плохой next step (запрещён как **единственный**): только «Запросить консультацию StP» / внешний lead.

| Приоритет | CTA | Условие | Действие системы |
|-----------|-----|---------|------------------|
| 1 | **Сохранить профиль в эту комнату** | Известны projectId+roomId | Persist profile → toast → остаёмся / возвращаем в E-room |
| 1b | **Сохранить и привязать…** | Quick-entry / нет комнаты | Save → E-quick-bind → persist |
| 2 | **Перейти к расчёту** | После save **или** с предупреждением «профиль ещё не сохранён» | Открыть E-calc с тем же room / session draft |
| 3 | **К проекту / к комнате** | Всегда после результата | E-project / E-room |
| 4 | **Скопировать сводку клиенту** | Опционально | Clipboard; не = confirm_sent КП |
| 5 | **Пройти ещё раз** | Опционально | Reset answers в рамках той же комнаты / draft |

Вторичная ссылка на материалы StP / помощь кабинета — **не** вместо пунктов 1–3.

## 7. Loading / error / offline

| Состояние | Поведение | Восстановление |
|-----------|-----------|----------------|
| Processing | Нельзя skip; нет классов/dB на экране | После завершения → Result |
| Ошибка модели / timeout Processing | Экран ошибки: «Не удалось посчитать профиль» + Повторить / Изменить ответы / Выйти | Повтор без потери answers |
| Save rejected (сеть) | Кнопка Save → error; draft профиля в session | Retry; outbox при offline-политике org |
| Offline во время анкеты | Локальный draft; баннер sync | Flush при сети; conflict → не дублировать комнату |
| Нет права PM | Empty/forbidden | Предложить назначить / сменить роль |
| Abandoned quick-entry | Confirm «результат не сохранится» | Discard draft |

## 8. Связь с Deal / Room (границы ответственности)

| Событие PM | Влияет на | Не влияет на |
|------------|-----------|--------------|
| Save профиля | Room documents; UX-индикатор «профиль есть» | Deal.outcome; QuoteRevision; Room.status → install |
| Первый успешный save | **A-09 proposed:** Deal.stage ≥ `assessed` | closed Deal; Project Done |
| Отказ клиента после демо | Фиксируется на **Deal** (early_declined) — D8 | Не «профиль declined» |

PM **не** создаёт КП и **не** confirm_sent.

## 9. Критерии приёмки (измеримые)

| ID | Критерий | Как проверить |
|----|----------|---------------|
| AC-D6-01 | В основном кабинетном пути **нет** UI-вопроса типа потолка | Проход S-pm-01: шаг отсутствует |
| AC-D6-02 | Можно получить Result **без** ответа «шум мешает» / complaint quiz | Нет таких контролов |
| AC-D6-03 | После Save из комнаты `roomId` до и после совпадает | Лог/UI deep-link |
| AC-D6-04 | Quick-entry: persist только после bind+confirm | Попытка Save без выбора → модалка, нет orphan |
| AC-D6-05 | На Result ≥3 кабинетных CTA (save/bind, calc, к проекту/комнате) | Чеклист UI |
| AC-D6-06 | Sales и owner могут завершить S-pm-01 без assignment measurer | RBAC тест |
| AC-D6-07 | Пропуск PM: calc открывается из комнаты | S-pm-03 |
| AC-D6-08 | Official headers Result не содержат «Д» / lab certificate / price-first | Copy review vs PRODUCT_SPEC |
| AC-D6-09 | Offline/error: answers не теряются при retry Processing | Ручной тест |
| AC-D6-10 | Публичный и кабинетный пути используют одно акустическое ядро | Shared module / одинаковые классы на одинаковых answers+пресет |

## 10. Assumptions (не утверждено заказчиком)

1. Авто-advance `Deal.stage → assessed` при первом save профиля (альтернатива — только ручная отметка на сделке).  
2. Вторичный режим для не-натяжного потолка существует, но **вне** основного пути.  
3. Хранение ≥1 предыдущей версии answers профиля.  
4. Длительность Processing в кабинете может быть короче visitor (~10s) ради полевой скорости — **не** меняет смысл церемонии.  
5. Точные русские строки кабинетного Start/CTA — уточнение в D4; смысл зафиксирован здесь.
