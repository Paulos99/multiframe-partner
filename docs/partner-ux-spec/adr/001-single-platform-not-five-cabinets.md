# ADR-001 — Одна платформа ≠ пять кабинетов

- **Статус:** Accepted (`rev-gate-a-approved-20261022`)
- **Дата:** 2026-10-22
- **Контекст:** D1, D2, D2a, D3

## Контекст

В коде пять `*Home.tsx` с разным chrome, но ядро — один `ObjectsPanel` / `RoleWorkspace`. План и заказчик требуют профессиональную платформу для потолочных компаний, а не пять визуальных клонов.

## Решение

Одна информационная архитектура и общие экраны доменов (проект, комната, сделка, инструменты, академия). Роли отличаются:

- домашним фокусом (inbox);
- пунктами навигации;
- RBAC и CTA на общих экранах;
- next actions.

Homes — тонкие маршрутизаторы фокуса, не отдельные продукты.

## Отвергнутые альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| Пять независимых мини-приложений | Дублирование IA, расхождение модели, невозможный handoff |
| Один универсальный ObjectsPanel для всех без смены фокуса | Crew и sales видят чужую работу; нет «сегодня» |
| Копировать ObjectsPanel в пять CSS-тем | Тот же антипаттерн «разная обёртка» |

## Следствия

- Screen specs (D4) пишутся на экраны доменов + матрица видимости, не «AdminObjects vs SalesObjects».  
- Критерий регресса: появление пятого параллельного списка сущностей = нарушение ADR.
