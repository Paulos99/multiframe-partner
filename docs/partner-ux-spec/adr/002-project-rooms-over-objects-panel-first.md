# ADR-002 — Иерархия Проект → Комнаты вместо ObjectsPanel-first

- **Статус:** Accepted (`rev-gate-a-approved-20261022`)
- **Дата:** 2026-10-22

## Контекст

Модель shared уже разделяет `Project` и комнаты (`JobObject` + `projectId`). UI фактически строит карточки проектов внутри `ObjectsPanel`, параллельно существуют неподключённые `ProjectsCabinet` / `ProjectDetail`. Коммерция (Deal/Quote) привязана к `projectId`. Ментальная модель потолочников: объект клиента = адрес/квартира с несколькими помещениями.

## Решение

Канон IA: **список проектов → карточка проекта → комнаты**. Комната — место замера, PM, calc, документов и монтажа. Deal/КП — на уровне проекта. «Мои комнаты» / канбан — views, не замена иерархии.

Логику orphan `ProjectDetail` использовать как референс поведения, не как второй навигационный корень.

## Отвергнутые альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| **ObjectsPanel-first** (плоский/полуплоский список объектов как главная сущность) | Ломает КП на несколько комнат; Deal@projectId спорит с UI; провоцирует дубль клиента/адреса |
| Проект только как папка-ярлык без экрана | Пользователь не видит предварительный итог и сделку в одном месте |
| Отдельные вкладки «Проекты» и «Объекты» как равные корни | Два источника истины (уже болела координация) |

## Следствия

- Save calc / PM всегда в комнату проекта.  
- Создание «объекта без проекта» исключено из целевого пути.  
- Переименование в UI: «комната», не «объект» (техническое JobObject может остаться до D5).
