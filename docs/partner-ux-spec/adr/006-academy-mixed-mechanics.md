# ADR-006 — Академия: смешанные механики, не «всё = чат»

- **Статус:** Accepted (`rev-gate-a-approved-20261022`)
- **Дата:** 2026-10-22

## Контекст

Сейчас AcademyScreen = sell Multiframe + objections (чат/сценарные тренажёры). Заказчик: чат — основной для продаж/возражений; монтаж, расчёты, практика — другие интерактивные механики. `context: training` ∉ KPI.

## Решение

В IA закладывается **хаб Академии** с типами тренажёров:

- продажи / возражения → чат-симуляция — **приоритет первой версии**;
- монтаж / расчёты / практика → отдельные **не-чат** механики — далее (слоты в хабе уже есть).

Gate A не специфицирует деревья сценариев (это D9). Запрещено проектировать навигацию так, будто единственный тип контента — chat trainer.

## Отвергнутые альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| Свести всю Академию к чату | Не учит монтаж/раскладку; ложный skill transfer |
| Заменить чат продаж на тесты с кнопками | Хуже для возражений (явное требование заказчика) |
| Смешать Academy attempts в партнёрский KPI | Ruling: training∉KPI |

## Следствия

- E-academy-hub в D3 с слотами механик.  
- D9 обязан описать не-чат форматы.  
- Материалы (PDF/видео) остаются библиотекой рядом, не подменяют тренажёры.
